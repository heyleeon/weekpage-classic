> **2026-10-11 冻结，不再排期。** 下面是冻结时没做完的切片，原样留着：验收清单和已知缺口。其中的 bug 欢迎提 PR；新功能不收。

每个切片三块：**目标**、**退出条件**（能验收的）、**设计草稿**。设计草稿只放已经讨论过的结论和待定项，没有就空着。

## 切片 1：节假日数据续期

**目标**：日历上 2027 年的法定假日、调休和节日名正常显示。

**退出条件**：
- 打包的 `frontend/src/lib/holidays-data/chinese-days.json` 覆盖 2027 全年。
- 断网首次启动，日历上也能看到 2027 年的假日。
- `bash scripts/check.sh` 全绿，新版本装机。

**设计草稿**：
- 现在打包的数据里，法定假日只到 2026-10-07，调休上班日只到 2026-10-10。
- 联网时不用等发版。`frontend/src/lib/holidays.ts` 每周在后台从 jsDelivr 拉一次 chinese-days 的最新文件，存进设置库的 `cache:holidays`，失败不出声。所以真正要续期的，是断网兜底和首次启动用的这一份。
- 续期做法：国务院发布 2027 年放假安排、chinese-days 发新版后，升级这个依赖，再用 `holidays.ts` 文件头注释里那条 `node -e` 命令重新生成打包文件。

## 切片 2：Windows 真机验收

**目标**：在 Windows 11 真机上走通下面的清单，能日用。

**退出条件**：清单 9 项都过了；没过的每一项都开成了待办。

**设计草稿**：
- 现状：CI（`.github/workflows/check.yml`，windows-latest）每次推送跑 `scripts/check.sh be` 和 `pnpm -C frontend tauri build --debug --bundles nsis`，所以能编译、能打 NSIS 包。真机一次都没跑过。
- 分工：用户在真机上操作，agent 出命令、判读结果。
- 身份：`tauri build` 出的是开发身份（WeekPage Dev，快捷键 Ctrl+Alt+Shift+Space）。要验 Ctrl+Alt+Space 和安装后的名字「WeekPage」，用 `pnpm -C frontend tauri:release`。
- 平台差异都收在 `backend/src/platform/`，出问题先看那里。
- 清单：
  1. Win11 真机 clone 前，先开「开发者模式」并执行 `git config --global core.symlinks true`。clone 后跑 `bash scripts/check.sh be`、`pnpm -C frontend tauri build --bundles nsis`。
  2. NSIS 安装（当前用户）。开始菜单搜「WeekPage」打开；再打开一次，只有一个进程，原窗口被叫出来。
  3. Mica（Win11 build ≥ 22000）生效；Win10 不设效果，外圈是实色，没有白块。
  4. 安装版的 Toast 显示正确的名字和图标；睡眠唤醒后补发。
  5. Ctrl+Alt+Space 呼出、再按隐藏；窗口置顶且不进任务栏；失焦隐藏的去抖（失焦后等 150 ms 再判）够不够；托盘左键切换窗口、右键出菜单。
  6. 微软拼音：组合态 Esc、回车选词；Ctrl+C / V / Z / A；Windows 不设 Ctrl+Q。
  7. 拖动在 Windows 上同样可用。
  8. 语言与外观：中文 Windows 上 NSIS 安装器是中文，英文系统是英文，不弹语言选择框。黑夜主题（含跟随系统）下，窗口外圈仍然透明 / Mica，没有被 `color-scheme: dark` 涂成实色。
  9. 逾期红点：有逾期的关键点时，托盘图标右上角出现白边红点（16 / 24 / 32 px 的托盘缩放下都看得清）；勾掉后恢复原图标。

## 切片 3：macOS 人工验证

**目标**：把只能用户亲手验的事，在装好的 `/Applications/WeekPage.app` 上验一遍。

**退出条件**：下面 14 项逐条验完；没过的开成 bug，或在 `docs/memory/decisions.md` 里记下「不修」。

**设计草稿**：
- 为什么只能人工：真 App 是菜单栏应用，agent 拿不到它的操作权限（见 `docs/memory/lessons.md` 里「菜单栏应用（LSUIElement）拿不到 computer-use 权限」那条）。目前拖动、手势、滚动都只用合成事件测过。
- 清单：
  1. **⌃⌥Space 与系统输入法切换**：系统项开着时，用物理键盘按 ⌃⌥Space，看是呼出 WeekPage 还是切输入法（合成按键测过，不算）。去系统设置关掉「选择输入法菜单中的下一个输入法」后再呼出一次，首启提示和设置面板里的冲突说明应当消失。或者在设置里录一个新快捷键。
  2. **通知**：对「“WeekPage” Notifications」点允许（改名后 bundle id 变了，要重新允许）。建一条 5 分钟后的待办提醒：窗口隐藏、屏幕熄灭时，准点（或醒来后）出现横幅。退出期间到点的，下次启动合并成「错过 N 条提醒」。点横幅能叫出窗口。
  3. **Spotlight**：⌘Space 输入「WeekPage」回车；已在运行时，只叫出原窗口。
  4. **开机自启**：注销 / 重启后，自动在后台启动（不弹窗）。托盘或设置里关掉后，登录项消失。
  5. **核心流程在真 App 里走一遍**，重点是浏览器预览的假后端不支持的：关键点改名；详情页改名、改日期、提醒开关、删关键点、删任务、查看历史；收件箱「删掉」和 Toast「撤销」。
  6. **快捷键与菜单**：托盘菜单各项、Esc 隐藏、⌘W、⌘1 / ⌘2、⌘Q、⌘N、⌘F、⌘Z 撤销 Toast；输入框里的 ⌘Z 不被拦截。
  7. **真鼠标拖动**：
     - 日历条目：按下后移动 4 px 就浮起，不用长按。能拖到别的日期：日程、提醒、检查点、任务的开始和截止都要试。开始拖到截止之后，应当被拒绝并弹提示。
     - 边缘翻周：拖到网格上下边缘停 400 ms，自动翻周；放下后点一次「撤销」，能整体还原。
     - 其他：三列之间跨列拖动；拖动期间失焦不隐藏；Esc 取消拖动。
  8. **中文输入法**：拼音回车选词时不提交（日历输入框、收件箱、添加待办、+ 关键点、详情页都试）；候选窗显示在面板之上；搜狗、系统拼音等别的输入法也各试一次。
  9. **托盘切开机自启后再呼出**：设置面板里的值跟上（呼出时会刷新快照）。
  10. **窗口呼出的遗留项**：Safari 全屏下呼出，且能打字；两块缩放不同的屏上，光标在哪块屏就在哪块屏居中、大小不跳；首次呼出有没有闪白或空白透明窗（lessons 里记过一次偶发的整窗全透明）；点击面板时，前台应用保持不变；开「减少透明度」后，窗口外圈变实色。
  11. **视觉**：工具栏双击不再最大化；动画真的在播（卡片 FLIP、弹窗退场、「回到今天」淡入淡出、翻周滑动）；深色主题对稿。
  12. **日历翻周**：
      - 触控板：上下滑时，日历行跟手；停手后对齐到整周；惯性不会多翻，也不会卡在半行。
      - 鼠标滚轮：滚一格，正好翻一周。
      - 在某一天里滚动：那天的条目多到能滚时，先滚条目；滚到头后再开一次手势，才翻周。
      - 拖空白处：按住空白处上下拖能翻周，甩一下多翻一周；拖完后，双击空白处照样能新建。
      - 键盘：↑ ↓ ← → 翻周，T 回到今天；「回到今天」的箭头方向对。
      - 设置：「第一行 = 上周」在呼出窗口时生效。
      - 语言：切到 English 后，窗口、托盘菜单、提醒通知、快捷键冲突通知都变英文；在中文 macOS 上，「跟随系统」解析成中文（靠 `CFBundleLocalizations`）。
  13. **系统层文字**：
      - 中文和英文系统里，访达、启动台、Spotlight、通知横幅里的 App 名都是「WeekPage」（`.app` 文件名 `WeekPage.app`）。
      - 调度中心（Mission Control）里的窗口名是「WeekPage」，中英文相同。
      - 黑夜主题下，设置面板与详情页的滚动条、输入框光标和占位符是深色的（`color-scheme`）。
  14. **逾期的关键点**（规则见 ui-spec §9.3）：
      - 给一个关键点设成昨天的日期：窗口隐藏后，菜单栏图标右上角马上出现红点（浅色 / 深色菜单栏、菜单展开高亮时都看得清，点图标照样弹菜单）。勾掉它再隐藏窗口，红点消失。
      - 第二天 09:00（或 09:00 后启动）收到一条「N 步逾期：…」通知，当天到期的在下一行；同一天不重复。
      - 详情里拖一个没日期的关键点：拿起、上下拖、放下，全程详情框不变高、不跳。
      - 详情里左滑 / 右滑一行（鼠标和触控板两指都试）：行本身不动，「删除」从右端、「完成 / 取消完成」从左端以圆角色块盖进来；圆圈、日期、竖线都在原位，行的左右两头没有粉色 / 绿色细边。卡片里的关键点行照旧整行滑动，也没有细边。

## 切片 4：小缺口与待用户拍板

**目标**：清掉日用中已知的小毛病，并让待拍板的事有结论。

**退出条件**：
- 待拍板那一条有了答复，并已落地。
- 下面每一条，要么修掉，要么在 `docs/memory/decisions.md` 里记下「不做」和理由。
- `bash scripts/check.sh` 全绿。

**设计草稿**：
- **待用户拍板**：拖关键点到别的日子时，要不要把正文里的日期一起改（「等审批 · 10/1 查」拖到 10/5 变成「10/5 查」）。这是实现时顺手加的，没问过用户，见 decisions 2026-10-01 11:04:52。不要的话，去掉 `frontend/src/lib/calendar.ts` 的 `planCalMove` 里用 `retargetDateText` 改写正文的那一步，再删这个函数和它的测试。
- **已确认还没做的两条 P2**（规格里标的是 P2 或「可后做」）：
  - 速览胶囊里点「收件箱」那一项，应当切到任务页并把左栏切到收件箱页签（ui-spec §3）。现在点哪里都只是 `setPage("tasks")`（`frontend/src/components/calendar/TodayPill.tsx`），要再加 `setLeftTab("inbox")`。
  - 快捷键冲突通知被点击后，应当打开设置（ui-spec §16.1）。现在点任何通知都只是呼出窗口（`backend/src/shell/mod.rs` 里的 `on_notification_click`）。托盘菜单的「设置…」已经有「先呼出再跳到设置」可以复用。
- **已知的小缺口**：
  - 日历双击输入不解析英文日期词（tomorrow、mon），日期由格子决定；`classifyKeyPoint` 只认中文措辞，英文的「Wait for…」会被判成「我来做」。改这两处都要先改规格（ui-spec §18、§19.1）。
  - 系统语言变了，托盘菜单不会实时换语言，要等改设置或重启（前端会听 `languagechange`，Rust 侧的托盘没有）。
  - 今日速览胶囊没设最大宽度，任务名很长时会把它撑宽（`TodayPill.module.css`）。
  - 快捷键键帽里的「Space」写死成英文，macOS 中文系统里该是「空格」（`frontend/src/components/settings/accelerator.ts` 的 `keycaps`）。
- **要在真窗口里看一眼，再决定修不修**：
  - 窗口最小高度（680）时，设置面板要滚动才看得到最后一节，底部也没有渐隐提示（设置面板用的 `Modal` 没接 `ScrollFade`）。
  - 打开行内「+ 关键点」输入时，下面那张卡会短暂压住正在长高的卡，随后归位。

## 切片 5：日程详情（地点等）

**目标**：日程可以有详情，能看、能改地点和结束时间。

**退出条件**：
- 日程能打开详情，里面能看到和修改地点、结束时间。
- `EventInput` 带 `location`；Rust 写命令、`bindings.ts`（`bash scripts/gen-contracts.sh`）、浏览器预览的 mock 一起改好。
- 撤销照常可用；`bash scripts/check.sh` 全绿。

**设计草稿**：
- 现状：`events` 表和 `Event` 类型已经有 `location` 列，写入参数 `EventInput`（`backend/src/model.rs`）没有，所以地点现在只能写在标题里。结束时间已存库：日历条目悬停显示「15:00–17:00」，双击编辑时预填「15:00-17:00 标题」。
- 早先的想法：加一个小浮层，同时给 `EventInput` 加 `location`。
- 待定：浮层的样子、怎么打开。
- 需求依据：1.0《需求说明》§2、§2.1（没随本仓公开）。
