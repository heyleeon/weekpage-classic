# WeekPage · 界面实现规格（ui-spec）

> 读者：要写或改界面的 agent。用途：界面行为的唯一规格，改行为就改这里，并在 `docs/memory/decisions.md` 记一笔。开发以本文为准。
> 需求、视觉规范、设计图没随本仓公开，见 `AGENTS.md` 的「权威文档」（正文里的「v2 01-1」「V3-A」等编号指设计图）；技术方案（分层、写数据的规则、窗口与系统集成的取舍）见 [`architecture.md`](architecture.md)。本文不写实现代码。

## 0. 总则

### 0.1 怎么读

| 约定 | 说明 |
|---|---|
| 优先级 | **规则听《需求说明》；布局和交互听 v2 导出图；材质、配色、圆角、间距听 V3**（A = 白天，C = 黑夜）。三者冲突、或用户后来改过的地方，正文已经裁决并写成规则，照正文做；改动记录在 `docs/memory/decisions.md`。 |
| 标记 | **≈**：从图上量的估算值（±2px 内可调）。**【无稿·推导】/「无稿，按规范推导」**：图里没画，按需求和令牌补的默认做法，直接照做。 |
| 单位 | px（CSS 像素 = macOS pt）。V3 导出图是 1×（窗口 1280×860）；v2 导出图是 2×，已换算。 |
| 颜色 | 只写令牌名（§0.2），组件里**不写死颜色**。切白天 / 黑夜只换变量值，组件不分两套。 |
| 字体 | 系统字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Segoe UI Variable", "Segoe UI", "Microsoft YaHei UI", sans-serif`（`--font-family`，在 `frontend/src/design/tokens/semantic.css`）；数字、日期、时间一律 `font-variant-numeric: tabular-nums`。V3-C 里日期用的等宽字体不采用。 |
| 图标 | Phosphor（`@phosphor-icons/react`）。界面图标 regular；日历前缀用 fill（`circle` / `bell` / `play` / `flag`）。文中直接写图标名。 |
| 日期写法 | `M/D` 不补零；星期写「周一…周日」；时间 24 小时 `HH:MM`。文中例子的「今天」= **2026-09-30 周三**（和 `backend/src/seed.rs` 的演示数据一致，演示时钟 10:00）。英文界面的写法见 §0.8。 |
| 跨日 | 「新的一天」= 本地 00:00。待办自动归档、时间条前进都是「今天」的函数（查询时推导），由 Rust 的 `clock://day-changed` 事件和每次呼出窗口时刷新（architecture §12）。 |
| 术语 | **日程** = event；**待办** = todo；**提醒**（日历上）= 待办设了提醒日；**任务** = task；**关键点** = 我来做 `do` / 等别人 `wait` / 检查点 `check`；**记一笔** = `note`（和关键点同一条时间线，但不算关键点）；**逾期的关键点** = 有日期、日期已过、还没勾的关键点（§9.3）；**收件箱整理** = 今天 / 定日期 / 变任务 / 删掉 四个去向；**归档** = 任务手动归档 + 待办次日自动归档；**纸** = 不透明内容区；**胶囊** = 玻璃分段按钮组；**浮层** = 带遮罩的模态面板；**弹层** = 无遮罩、锚定在触发元素旁的面板；**Toast** = 底部提示条。 |

### 0.2 令牌（CSS 变量）

组件里一律用语义令牌名（`--paper`、`--text-muted`、`--ev`、`--rm-soft`、`--capsule-on`、`--scrim`、`--modal`、`--elevated`、`--radius-*`…），不写死颜色；切白天 / 黑夜只换变量的值，组件不分两套。

令牌的值和用途**不抄在本文**，看 `frontend/src/design/tokens/{primitive,semantic}.css`（原始色、语义名）和 `frontend/src/design/themes/dark.css`（黑夜值），要改就直接改这几份。颜色字面量只许出现在 `primitive.css`；三层的关系（原始色 → 语义 → 组件）见 `AGENTS.md` 的「目录速览」。组件级的 `components.css` 归本仓。

### 0.3 主题与平台差异

- 主题：设置 `跟随系统 / 白天 / 黑夜`，默认跟随系统；系统切换时实时跟着变。白天 = V3-A，黑夜 = V3-C，只换变量值。
- `<html data-theme="light|dark">`（手动时）；跟随系统时不写属性，靠 `prefers-color-scheme`。无原生毛玻璃时 `<html class="no-vibrancy">`。

| 项 | macOS | Windows |
|---|---|---|
| 全局呼出（默认，可在设置里改） | ⌃⌥Space | **Ctrl+Alt+Space**（Alt+Space 会吃掉系统窗口菜单，ChatGPT 也默认用它） |
| 切换页面 | ⌘1 / ⌘2 | Ctrl+1 / Ctrl+2 |
| 胶囊里的快捷键文案 | 「⌘1」「⌘2」（稿上写「Cmd 1」只是 Pen 字体缺 ⌘ 字符） | 「Ctrl 1」「Ctrl 2」 |
| 窗口毛玻璃 | 原生 vibrancy，窗口圆角 26 | Win11 Mica（系统圆角约 8）；Win10 用 `--window-fallback` 实色 |
| 隐藏窗口 | Esc（§15.4 链最后一层）/ ⌘W | Esc / Ctrl+W |
| 退出 | ⌘Q / 菜单栏图标菜单「退出 WeekPage」 | 托盘图标菜单「退出 WeekPage」 |

### 0.4 动效

统一 150ms ease-out（≈），个别组件写明自己的时长。系统开了 `prefers-reduced-motion` 时，所有动画时长都设成 0。

### 0.5 显示状态怎么推出来（全文通用）

任务卡上显示的状态按下面的顺序取第一个命中的：
1. `status = done`（已完成）→ **已完成**
2. 有截止，且今天 > 截止 → **逾期**
3. 今天 < 开始 → **未开始**
4. 否则用存的值：**推进中**（`active`）/ **等待中**（`waiting`）

「未开始」和「逾期」都是推出来的，不能手动选（详见 §10.4）。

### 0.6 数据口径

字段、表结构、命令以代码为准（`backend/migrations/0001-init/up.sql`、`backend/src/model.rs`、`backend/src/commands.rs`），数据怎么写见 architecture.md §6。本文出现的 `start` / `due` / `column` / `order` / `done_at` 等是口径说明：分别对应 `start_date` / `due_date` / `board_column` / `sort_key` / `done_date`。界面上没有「当前」关键点（§9.3）：存的 `is_current` / `current_since` 不读来显示，`current_since` 只在算「等别人 N 天」时当起点（§13.3）。

### 0.8 语言（i18n）

- **两种界面语言**：简体中文（zh-Hans，**源语言**）和英文（en）。界面上所有文案的原文在 `frontend/src/i18n/locales/{zh-Hans,en}/<分区>.ts`，中文为准：本文只在规则要用到时引用文字，不再列文案表，想知道某处写什么字去那里查。改中文必须同时改英文（tsc 和 `i18n.test.ts` 守：键对不上、缺复数形、空字符串都会失败）。实现见 architecture §9。
- **设置「语言」**（§16）：`跟随系统 | 简体中文 | English`，默认跟随系统。选项名永远用各自的语言写（「简体中文」「English」）。
- **跟随系统怎么判**：看系统首选语言列表，第一个简体中文（zh、zh-CN、zh-SG、zh-Hans-*，不分地区）或英文（en*）的条目决定；繁体中文（zh-TW、zh-HK、zh-MO、zh-Hant-*）没有对应文案，和其他没有文案的语言一样跳过；列表里两种都没有 → 英文；列表为空 → 中文。窗口、托盘菜单、App 名用同一条规则（前端 `resolveLang` / Rust `i18n::resolve` / macOS 匹配 `InfoPlist.strings`）。系统语言变了，窗口实时跟着变；托盘菜单在设置变化或下次启动时更新。
- **切换**：点了立刻生效，不重启、不重新加载数据；整张纸重新渲染，已经打开的浮层和 Toast 留在原处，不重放进场动画。已经显示出来的 Toast 文字保持切换前的语言，直到它消失。
- **日期写法**随语言：中文「9月 2026」「9月30日 周三」「10/9 周五」「10月1日」；英文「September 2026」「Sep 30 Wed」「10/9 Fri」「Oct 1」。`M/D` 数字写法两种语言一样，星期从周一开始。
- **英文术语**（各分区统一，表头注释在 `locales/en/tasks.ts`）：日历 Calendar · 任务 Tasks · 待办 To-dos · 收件箱 Inbox · 关键点 step · 我来做 My move · 等别人 Waiting on · 检查点 Checkpoint · 记一笔 Note · 推进中 Active · 等待中 Waiting · 未开始 Upcoming · 逾期 Overdue · 已完成 Done · 归档 Archive。中文的「」在英文里写成弯引号 “ ”。
- **不翻译的**：用户自己写的内容（标题、关键点文字）、演示数据、产品名以外的专有名词。节日、节气名有英文（§2.4）。
- **识别规则不跟界面语言走**：时间识别（§18）中英文写法都认（英文写法见 §18「英文写法」）；关键点自动判型（§19）只认中文写法（英文「Wait for…」会判成「我来做」，点徽标手动改）。
- **Rust 自己显示的文字**（托盘 / 菜单栏菜单、提醒通知、「快捷键被占用」通知、原生窗口标题）也是两种语言，规则同上（`backend/src/i18n.rs`）。
- **系统层的名字**：macOS 上访达、启动台、Spotlight、通知横幅里的 App 名在所有系统语言下都是「WeekPage」（按系统语言换名字的机制保留，以后有中文名再分；不跟 App 内的语言设置走）；Windows 安装器按系统语言显示中文或英文，开始菜单里的名字固定是「WeekPage」。
- **设置「时区」**（§16）：`跟随系统（Asia/Shanghai）` 或任意 IANA 时区，默认跟随系统，和语言互相独立。它决定「今天」从几点算起、提醒触发时刻、历史里的时间；日历里存的日期是不带时区的纯日期，改时区不会挪动已有条目。改完立刻生效（前端 `lib/clock` + Rust `clock::set_timezone` 同步切换）。
- **地区不跟语言走**：节假日与调休、一周从周一开始、24 小时制按中国大陆，英文界面也一样（节假日名翻成英文，§2.4）。
- 英文通常比中文长：布局不为英文另做一套，放不下的地方英文用更短的说法（如收件箱整理按钮「Today / Date / Task」），或按控件自身的规则省略号 / 换行（见各分区文件里的注释）。

## 1. 窗口外壳

### 1.1 窗口

**结构**

```
<窗口>  透明 · 无系统标题栏 · 默认 1280×860
└─ .app-frame        圆角 26 · 内描边 1px --window-stroke · 背景透明（露出原生毛玻璃）
   └─ .paper         上下左右各缩进 8 · 圆角 18 · 背景 --paper · 1px --paper-stroke
      ├─ .toolbar            （§1.3）
      ├─ .page               日历页（§2）| 任务页（§4）
      ├─ .today-pill         仅日历页（§3）
      ├─ .overlay-layer      浮层（盖住整张纸，§15）
      └─ .toast-layer        （§15.3）
```

**尺寸**：从 V3-A 量出来，窗口 1280×860，纸 1264×844（四边各留 8）。
- 默认尺寸 1280×860。
- 最小尺寸 1100×680【推导】（任务页 3 列的下限，与 §4.2 一致；常量在 `backend/src/shell/window.rs`），窗口可以拉大缩小【推导】。
- 屏幕可用区域比 1280×860 小时（比如 1366×768 的笔记本），取可用区域的 92%【推导】。

**窗口行为**

| 项 | 规格（实现上的取舍见 architecture §4） |
|---|---|
| 呼出 / 收起 | 全局快捷键是开关：隐藏时按下 → 在光标所在屏幕居中显示并聚焦；显示且有焦点时再按 → 隐藏；显示但没焦点（钉住时）→ 聚焦 |
| 默认快捷键 | macOS ⌃⌥Space；Windows Ctrl+Alt+Space；设置面板（§16）可录制修改 |
| 搜名字打开 | 在 Spotlight / 开始菜单搜「WeekPage」打开。**单实例**：已经在运行的话，只把已有窗口显示出来并聚焦，不开新窗口 / 新进程 |
| 出现位置 | 鼠标所在那块屏幕的工作区正中；不记忆上次位置 |
| 悬浮 | 永远在其他窗口之上（macOS 为非激活面板，能盖在全屏应用上；呼出时不把别的应用切走） |
| 失焦 | 默认**失焦自动隐藏**（像 Spotlight / Raycast），去抖 150ms；拖动中、浮层里的原生对话框、录制快捷键时不隐藏。设置里关掉「失焦时自动隐藏」= 钉住，窗口一直浮在最上层 |
| 拖动窗口 | 工具栏的空白处是拖动区，按钮和胶囊上不算。双击拖动区不最大化 |
| 红绿灯按钮 | 不显示。关窗口用 Esc / ⌘W，等于隐藏，不退出 |
| Dock / 任务栏 | macOS 不显示 Dock 图标（菜单栏图标常驻）；Windows 不进任务栏（托盘图标常驻）。托盘菜单：显示 WeekPage / 日历 / 任务 / 设置… / 开机自启 / 退出 WeekPage |
| 开机自启 | 默认打开（否则重启后快捷键失效、提醒弹不出来）；设置面板和托盘菜单都能关 |
| 呼出时的页面 | 停在上次的页面（日历或任务；在归档页收起的回到任务页）；日历回到「家」（第一行 = 今天所在的周，或设置「第一行 = 上周」时的上一周，§2.2）；浮层（任务详情、设置…）和弹层关闭。**这些在收起时就做完**（`shell://hidden`），不等下次呼出：呼出时一眼看到的就是干净的日历 / 任务页，不会先闪一下上次的详情面板。收起时关浮层不放退场动画。呼出时（`shell://shown`）再做一遍兜底（隔天、错过事件） |
| 快捷键被占用 | 注册失败时：设置面板里该项显示红字原因，并弹一次系统通知「快捷键 ⌃⌥Space 被占用，打开菜单栏图标 → 设置 换一个」（英文 "Shortcut ⌃⌥Space is taken: open the menu bar icon → Settings to pick another"；Windows 写托盘图标）。macOS 上被别的应用抢先注册时系统**不报错**，所以首次启动在窗口底部显示一次提示条「按 ⌃⌥Space 试试能不能收起；不行就去设置里换一个」 |

**状态**：显示 / 隐藏 · 前台 / 失焦 · 浅色 / 深色 · 毛玻璃可用 / 降级（Win10 或 macOS 打开了「减少透明度」时，`.app-frame` 底用 `--window-fallback`，玻璃去掉模糊、改用实色底，§1.4）。

### 1.2 纸

- 一个普通的实色 div：背景 `--paper`，圆角 18，`overflow: hidden`，上面放所有内容。
- 深色时多一圈 1px 的 `--paper-stroke`。
- 纸本身没有阴影，窗口阴影交给系统。

### 1.3 工具栏

**结构**

```
.toolbar   高 36 · 外边距 上 19 / 右 20 / 左 24（≈）· 横向排列，垂直居中，左右两端对齐 · 拖动区
├─ .page-title
│  ├─ .t-main      日历页「9月」｜任务页「9月30日」        26 / 700 · --text
│  └─ .t-sub       日历页「2026」｜任务页「周三」          26 / 400 · --text-muted · 左间距 8
└─ .toolbar-right  横向 · 间距 10（--toolbar-gap）
   ├─ .back-today     [↑ 回到今天] / [↓ 回到今天]       仅日历页，且视图不在「家」时
   │  （任务页 / 归档页这个位置是「归档 N」按钮，§14.1）
   ├─ .gear           [⚙]                             所有页面
   └─ .capsule.pages  [日历 ⌘1] [任务 ⌘2]
```

**尺寸**（胶囊从 V3-A 1× 量）
- 胶囊高 ≈35（`--capsule-h`），内边距 3，选中块高 ≈29；pages 胶囊宽 ≈184（每段 ≈87）。
- 齿轮：35×35 圆形按钮，`GearSix` 17px。
- 「回到今天」：高 35，左内边距 8、右 14，圆点与文字间距 6；圆点直径 20，里面是 11px 粗体箭头（`ArrowUp` / `ArrowDown`）。
- 最右的胶囊离纸右边 20，胶囊顶离纸顶 19。

**样式**
- **胶囊 / 齿轮 / 回到今天**：同一种玻璃材质（§1.4），圆角 99。
- **段**：圆角 99，左右内边距 12，13px。没选中是 500 字重 + `--text-2`；选中是 600 字重 + `--text`，背景 `--capsule-on`，阴影 `--segment-on-shadow`，浮在压暗一档的胶囊底（`--segment-track`）上。
- **快捷键提示**「⌘1」：10px，`--text-faint`，左间距 6。
- **齿轮**：图标 `--text-2`，悬停 `--text`。
- **回到今天**：文字 13 / 500 `--text-2`（悬停 `--text`）；圆点底 `--today`、箭头 `--on-today`（和网格里「今天」的日期圆同色，一眼能对上）。箭头指向今天在哪：**↑ = 今天在更早的周**（用户往后翻了），**↓ = 今天在更晚的周**（用户往前翻了）。

**状态**

| 状态 | 表现 |
|---|---|
| 没选中的段悬停 | 背景 `--fill-2`，文字变 `--text`【推导】 |
| 按下 | 不透明度 0.7【推导】 |
| 选中 | 白色内块 + 阴影，浮在压暗一档的胶囊底上（黑夜是亮一档的 `--capsule-on`，底更暗） |
| 键盘焦点 | 2px `--ev` 外框，间距 2【推导】 |
| 「回到今天」出现 / 消失 | 视图离开「家」时淡入（`--duration-fast`）；回到家后淡出（`--duration-exit` 120ms）再卸载，淡出期间不可点、读屏不读；淡出中又离开家就直接留下 |
| 任务页 / 归档页 | 「回到今天」的位置换成「归档 N」按钮（§14.1）；齿轮和页面胶囊不变 |

**交互**
- 点 [日历] / [任务]，或按 ⌘1 / ⌘2：切换页面，左边标题跟着变。浮层开着时，先关浮层再切页【推导】。日历和任务之间的切换是横着滑过去的（日历在左、任务在右，动画见下一条）；进出归档页不滑，直接换。
- **左右滑动换页**（触控板两指横扫，在工具栏下面的页面区域；手感照 macOS 三指切换桌面）：日历在左、任务在右，和工具栏胶囊的顺序一样，有明确的左右空间感。
  - 日历页手指往左滑，任务页从右边进来；任务页手指往右滑，日历从左边进来。往没有页面的那边滑（日历页往右、任务页往左），页面只被拉动一点（越拉越沉，最多 56px），松手弹回，不换页。不会循环。
  - 两页像两个桌面并排：都一直挂着，没显示的那页停在自己那一侧的屏幕外（不可点、读屏不读）。滑动时不新建页面；切回来时页面还是离开时的样子（滚动位置等）。归档页只在显示时才挂上。
  - 页面跟着手指走，只平移、不变淡。走的距离是手指滚动量的 1.6 倍（触控板比页面窄得多）。两页之间空 40。拖过整页以后同样越拖越沉，最多再多走 56px，松手弹回来。
  - 松手交给弹簧，接着页面当时在屏幕上的速度走（拉过头时页面比手指慢得多，按页面的速度算，松手不会再往外甩一下）：甩一下（≥ 0.3px/ms）或拖过页宽的 25% 就过去，往回甩或没拖够就弹回。过去的那一刻就换页（标题、工具栏），不等动画走完。弹簧本身不过冲，约 0.17 秒走完九成、0.38 秒停稳。
  - 弹簧还没停稳就再滑：从页面当前的位置接着拖，往哪边滑都行（不用等动画走完）。
  - **手指抬起才动**：手指还在触控板上，页面只跟手，什么都不决定，停多久都一样；抬起的那一刻才按上面的规则决定过去还是弹回。网页从滚轮事件里看不出手指抬起，macOS 上由 Rust 读系统的滚动阶段告诉页面（`input://trackpad`）。
  - 抬起之后系统的惯性全部吞掉，不会滑到新页面里的行，也不会再换回去；手指再放上去才算新的一下。
  - Windows 和浏览器预览拿不到抬起信号，只能猜：系统惯性开始（滚动量连续 4 下平滑变小），或手指 60ms 没动，就当抬起；猜错了（滚动量又变大、反向、隔 40ms 以上才来，或停顿后又动起来）页面从当前位置接着跟手。停 120ms 以后才算新的一下。
  - 只认从页面空白处开始的横扫：从可滑动的行（§10.14）、输入框、能横向滚动的东西上开始的归它们自己；先竖着动的照旧翻周、滚列表。判方向和行一样：先动过 6px，横着多才算。浮层、弹层开着或正在拖东西时不换页。
  - 鼠标横向滚轮一格（行模式或 ≥ 50px）= 甩一下。
  - 开了减少动态效果：页面不跟手；横着滑过 48px，手指抬起时换页（拿不到抬起信号时滑够就换）。
  - 记住的「上次页面」在最后一次换页 0.7 秒后才写：写设置会刷新快照、重画两页，不能赶在滑动中间。
- 点齿轮或按 ⌘, / Ctrl+,：打开设置面板（§16）。提示「设置 ⌘,」（Windows「设置 Ctrl+,」）。
- 点「回到今天」或按 T：日历滑回「家」（§2.2）。提示「回到今天（T）」。
- 翻周：日历页上滚轮 / 触控板、拖网格空白处、↑ ↓ ← → 键（§2.2）。工具栏上没有翻周按钮。
- 工具栏空白处仍是窗口拖动区，三个控件上不算。

**标题怎么算**
- 日历页：「{显示范围第一天的月份}月」+「{年}」。比如显示 9/28–10/18，标题是「9月 2026」（与 V3-A 一致）。滚动中标题跟着第一行变。
- 任务页：「{今天的月}月{日}日」+「周X」，比如「9月30日 周三」。英文写法见 §0.8。

### 1.4 玻璃材质与浮起的头部

**玻璃**（`components/ui/Glass.module.css`，值在 `components.css` 的 `--glass-*`，白天 / 黑夜各一套）
- 所有浮起来的按钮共用这一种：工具栏胶囊、齿轮、回到今天、归档 N、今日速览胶囊、Toast、左栏页签和 +、「+ 新任务」、任务标题的玻璃胶囊。
- 做法：轻模糊 4px + 提高饱和度，半透明底，一圈左上 / 右下两角发亮的细边，内侧边缘一圈白光。WebKit 做不到把背后的内容掰弯（见 decisions.md 2026-10-07 07:30:12），玻璃感只靠这几样。
- 浮得更高的（速览胶囊、Toast）用更大的阴影 `--glass-shadow-float`。
- 无原生毛玻璃时：底改成 `--capsule-solid`，去掉模糊。
- 分段胶囊：胶囊底压暗一档（`--segment-track`），选中块白底 `--capsule-on` + 阴影 `--segment-on-shadow` 浮在上面。

**内容从玻璃下面流过**
- 任务页右栏的 TaskHeader、左栏的页签行浮在列表上面。列表顶部留出头部的空间（右栏 40 = 标题 28 + 12，左栏 45 = 页签 35 + 10），所以静止时位置不变；往下滚时卡片 / 待办从头部下面滑过。
- 列表最上沿 14px 渐隐到纸色（`ScrollEdge`），滑出去的内容是淡掉，不是被切断。
- 头部只有按钮接收鼠标，空白处的滚轮和点击落到下面的列表。
- 卡片滚到「任务 · N 件 · 逾期」下面时，这一组字淡入一个玻璃胶囊，保证看得清；胶囊显示时挡住点击，不会点到下面的卡片。滚回顶部就消失。
- 收件箱页签：输入框不动，列表在输入框下面滚。
- 日历：网格往上伸到星期行底下，换周时上一周从星期行下面滑出来，星期行自带一层纸色到透明的渐变保证字清楚；底部 64 留白里露出下一周的开头，往下渐隐到纸色，速览胶囊浮在上面（§2.1）。

## 2. 日历页

### 2.1 页面布局

```
.calendar-page            占满纸，从上到下纵向排列
├─ .weekday-row           7 列：周一 … 周日
├─ .grid                  N 行 × 7 列（N = 2 | 3 | 4）；上下各多渲染一周缓冲行（裁在可视区外、不可聚焦，供滑动时露出，§2.2）
│  └─ .day-cell × 7N
└─（.today-pill 绝对定位，浮在 grid 底部之上，§3）
```

| 项 | 数值 |
|---|---|
| 网格左右边距 | 离纸边 12。网格宽 = 纸宽 − 24（默认 1240），每列 = 1/7（≈177） |
| 星期行 | 高 ≈26。文字 11px `--text-muted`，左内边距 8；底边 1px `--line`，贯穿整个网格宽 |
| 行高 | 各行等高 =（网格可用高 − 底部留白 64）÷ N。3 周 ≈230，2 周 ≈346，4 周 ≈173 |
| 底部留白 64 | 速览胶囊高 38 + 离底 16 + 10 的空隙。行高不算它；这里露出下一周的开头，往下渐隐到纸色，速览胶囊浮在上面（§1.4） |
| 行分隔 | 行与行之间 1px `--line`（最后一行和下面露出的下一周之间也有）。**没有竖线，没有底色，周末也不着色**（V3：「格子只有横线」） |

### 2.2 显示范围与翻周

**范围**
- 每周从周一开始。范围的第一天 = 锚点那周的周一（锚点 = 第一行那周的周一）。
- **家**（home）= 打开窗口时、回到今天时第一行显示的那一周，由设置「第一行」（§16）决定：**本周**（默认，今天总在第一行，与稿一致）或**上周**（今天在第二行，能看到上周）。
- 例子（今天 9/30 周三，第一行 = 本周）：3 周显示 9/28–10/18；2 周显示 9/28–10/11；4 周显示 9/28–10/25。第一行 = 上周时 3 周显示 9/21–10/11。
- 回到家的时机：每次呼出窗口；按 T / 点「回到今天」；改「第一行」设置；跨天时如果视图本来就在家（停在家的日历跟着新的一天走，用户翻走的不动）。
- 切换 2 / 3 / 4 周（设置面板）时锚点不变，第一行还是同一周。
- 跨天：到 00:00 自动刷新「今天」高亮和「过去变淡」；每次呼出窗口时也刷新一次【推导】。
- 应用里的「当前时间」要能注入（演示 / 测试时固定成 2026-09-30）【推导】。

**翻周**（都是整周，没有半周停留）

| 操作 | 结果 |
|---|---|
| 鼠标滚轮一格（整格事件：行模式，或像素 ≥ 50） | 翻一周：向下滚 = 更晚一周，向上滚 = 更早一周 |
| 触控板两指滑动（小的像素增量） | 各行跟着手指走，停下 120ms 后吸附到最近的整周。很短的一下（≤ 3 个事件、不到半行，WebKit 把慢速滚轮一格报成一个约 4px 的事件）也翻一周 |
| 横向滑动 | 不翻周，换页（§1.3「左右滑动换页」） |
| 捏合缩放（ctrl + 滚轮） | 不处理 |
| 在能滚动的格子列表上滚 | **列表优先**：这一下手势从能往那个方向滚的格子里开始，就只滚格子，不翻周；格子滚到底后，下一次手势才翻周 |
| 按住网格空白处拖（竖向移动 ≥ 4px） | 「抓住」各行跟着走，光标 grabbing；松手吸附到最近的整周，快速甩一下（最后 100ms 速度 ≥ 0.5px/ms）多走一周。横向先动的按压不算抓取。抓取结束时的单击 / 双击被吞掉，不会打开新建输入框 |
| ↑ / ← 、↓ / → | 前一周 / 后一周（日历页，没有输入框、浮层、弹层、拖动时） |
| T | 回到家 |
| 拖着条目停在网格上下边缘 | 翻周，见 §2.7 |

- **滑动**：每次换周（按键、滚轮一格、回到今天、呼出窗口、拖条目翻周）都从原位置滑过去：`--duration-card`（200ms）ease-out；开了减少动态效果时直接跳。一次跳很多周时只滑最后一行的距离，不会出现空白。连按 ↓↓ 会累加，标题直接显示终点。数据刚加载完的 300ms 内不滑。
- 抓取、滚动时正在打开的「新日程」输入框先按失焦规则保存（§2.6），再开始翻周。
- 网格在滑动时上下各露出缓冲行的一部分：上面的从星期行底下滑出来，下面的静止时也露在 64 留白里（§1.4）。缓冲行不可聚焦、读屏不读、点不了。
- 底部 64 的留白（速览胶囊那一块）也接收滚轮和抓取；星期行和速览胶囊上滚动不翻周。

### 2.3 日期格

**结构**

```
.day-cell  [data-date] [data-today] [data-past]
├─ .day-head          高 22 · 横向排列，垂直居中
│  ├─ .day-num        「28」|「30」（今天，蓝色圆）|「10月1日」（每月 1 号）

**尺寸**（V3-A）
- 格子内边距 上 5 / 左右 6（≈）。
- 普通日期数字的左缘和条目图标列对齐（离格子左边 ≈12）。
- 「今天」的圆 22×22，从离格子左边 6 处开始，数字在圆里居中。
- 节日小字在日期后面，间距 8。

**字体**
- 日期：13 / 500，`--text`，等宽数字。
- 每月 1 号写成「10月1日」，13 / 700。
- 今天：圆的底色 `--today`，数字 12 / 600，`--on-today`。
- 节日小字：10px，`--holiday`。

**状态**

| 状态 | 表现 |
|---|---|
| 默认 | 如上 |
| 今天 | 蓝色实心圆 + 白字 |
| 过去（日期早于今天） | 日期数字和节日小字都用 `--text-disabled`；格里的条目不透明度 0.45（V3-A 里 9/28、9/29 就是这样）。过去的格子照样可以双击新建、拖动排序【推导】 |
| 空 | 只有日期头 |
| 双击输入中 | 列表末尾多一个 `.cal-input` |
| 内容超出格高 | `.day-items` 在格内滚动，滚动条平时隐藏、悬停时显示细条，底部 16px 用 `--fade-card` 渐隐【无稿·推导】 |
| 拖动中 | 见 §2.7 |
| 深色 | 只换变量 |

**交互**
- 双击格子空白处（包括日期头，不包括条目本身）：在列表末尾出现输入框（§2.6）。
- 单击空白处：取消条目的选中状态。

### 2.4 日期头：节假日 / 节气 / 补班

| 情况 | 显示 | 依据 |
|---|---|---|
| 法定假日连休的第 1 天 | 节日全称：「国庆节」「中秋节」 | 稿 10/1 |
| 连休的第 2…N 天（周末也算在内） | 「简称 · 第几天」：「国庆 · 2」…「国庆 · 7」 | 稿 10/2–10/7 |
| 二十四节气 | 「寒露」 | 稿 10/8 |
| 调休补班日 | 「补班」，样式和节日小字一样 | 【无稿·推导】 |
| 同一天既是假日又是节气 | 用「 · 」连起来，假日在前；放不下就加省略号 | 【推导】 |
| 其他节日（七夕、重阳、圣诞…） | 不显示 | 【推导】：v2 稿和旧工具都只显示了法定假日和节气 |

- **颜色**：用 `--holiday`（V3 是灰色）。v2 里旧的红褐色 #B04A3A 不再用。补班也用灰色，因为「颜色只用在语义上」。
- **用户的旧习惯**（CalendarTask 截图）：每天都能看到节日、节气的名字，而且标出是第几天，比如「国庆节(第二天)」。v2 把它们挪到了日期旁边，写成小字「国庆 · 2」，信息没丢。旧工具里周末有底色，V3 去掉了。
- **数据**：法定假日和调休用 chinese-days 的 `chinese-days.json`（跟着国务院公告更新），打包一份在 `frontend/src/lib/holidays-data/`，联网时每周最多更新一次；节气用 chinese-days 的 `getSolarTerms` 算。细节见 `frontend/src/lib/holidays.ts` 文件头。本文里的节日例子（国庆 10/1–7、中秋 9/25–27、10/10 补班…）以数据源为准。
- **英文界面**（§0.8）：节日、节气、补班都有英文（「National Day」「National Day · 2」「Cold Dew」「Workday」），规则同上；数据里新出现、没有翻译的节日显示数据自带的名字。1 号的日期写「Oct 1」。

### 2.5 条目的统一结构 `.cal-item`

**结构**（需求 §4：`[前缀图标] [标题（可换行）] [时间（有才显示，靠右）]`）

```
.cal-item  [data-kind = event | reminder | checkpoint | start | due]  [data-state]
├─ .ci-icon    宽 10、高 16（= 第一行的行高）· 不伸缩 · 图标在里面居中，只和第一行对齐
├─ .ci-title   占满剩余宽度 · min-width 0 · 自动换行（overflow-wrap: anywhere）
└─ .ci-time?   不伸缩 · 左间距 ≥6 · 固定在第一行右侧（align-self: flex-start）
```

**尺寸**
- 最小高 18，内边距 1px 6px，行高 16，圆角 6，条目之间间距 2。
- 图标盒 10 + 间距 6，所以标题的起点离条目左边正好 22，所有条目左侧对齐（和设计稿里的 x22 一致）。
- 标题 12 / 400；时间 11 / 400，等宽数字。

**换行**：完整显示，**不截断**。时间固定在第一行右侧，标题在图标和时间之间换行，换下来的行和标题起点对齐，不会伸到图标或时间下面（稿：「和供应商吃饭，聊 / 下季度订单」）。

**五种来源 → 四种外观**

| kind | 来源 | 图标（phosphor fill） | 底 | 标题色 | 时间 | 图标色 |
|---|---|---|---|---|---|---|
| event | 日程 | 圆点 6×6 `circle` | 无 | `--text` | 有时间才显示，`--text-muted` | `--ev` |
| reminder | 待办设了提醒日 | `bell` 9–10 | `--rm-soft` | `--rm-text` | 设了提醒时间才显示，`--rm-text` | `--rm-text` 60% |
| checkpoint | 任务里带日期的关键点 | `bell` | `--rm-soft` | `--rm-text` | 不显示 | `--rm-text` 60% |
| start | 任务开始日（每个任务都有） | `play` | `--st-soft` | `--st-text` | 不显示 | `--st-text` 60% |
| due | 任务设了截止日 | `flag` | `--du-soft` | `--du-text` | 不显示 | `--du-text` 60% |

**标题怎么拼**
- event / reminder：用原标题。
- start / due：只写任务名，**不加**「开始 · 」「截止 · 」，靠图标区分。设计系统图里还留着「开始 · landing 文案」「截止 · 注册美卡」，那是旧写法，不采用。
- checkpoint（检查点，以及带日期的等别人）：检查点写「{任务名} · {关键点文字去掉日期片段}」，如「10/2 检查一遍初稿」→「交会议 PPT · 检查一遍初稿」；等别人写「{任务名} · 去查{关键点文字去掉开头的「等」、日期片段和结尾的「查」}」，如「等审批 · 10/1 查」→「注册美卡 · 去查审批」。「 · 」前后各一个空格。日期片段规则同 §19.1 D1/D2（`lib/keyPoint.ts` 的 `findDateTokens`）。

**说明**：黑夜里 V3-C 的图标看着是满色（`--rm` / `--st` / `--du`），规范写的是 `--x-text` 60%。按规范做，视觉上再微调。

**状态**

| 状态 | 表现 |
|---|---|
| 默认 | 如上 |
| 悬停 | event 加 `--fill-2` 底；彩色条目底色加深一点（亮度 ≈0.97，黑夜 ≈1.15）【推导】 |
| 选中（单击） | 内描边 1px `--ev`【推导】 |
| 过去日期 | 整个条目不透明度 0.45 |
| 拖起 / 原位幽灵 / 占位 | 见 §2.7 |
| 编辑中 | 条目原位变成输入框（§2.8） |

| 逾期的截止（任务没完成，截止日早于今天） | 在过去的日期里**也不变淡**，保持不透明度 1，好让人看到【无稿·推导】 |
| 逾期的检查点（§9.3：日期早于今天、没勾、任务没完成也没归档） | 也不变淡；换成截止的颜色（底 `--du-soft`、字和图标 `--du-text`，黑夜图标 `--du`），铃铛换成 `warning-circle` 10px |

**交互**

| 操作 | 结果 |
|---|---|

| 双击 event | 原位编辑（§2.8） |

### 2.6 双击新建 `.cal-input`

**结构**（按 V3-A：识别预览行在输入框**里面**。V3-C 把它画在框外，不采用）

```
.cal-input                  放在 .day-items 末尾
├─ textarea.ci-raw          随内容自动变高 · 不出现滚动条 · 一行时高 16
└─ .ci-preview              「↳ {时间} {标题}」
   ├─ .p-arrow  「↳」      --text-faint 11
   ├─ .p-time               --ev-text 11 / 600 · 等宽数字（有时间才显示）
   └─ .p-title              --text-muted 11
```

**尺寸和样式**
- 宽 = 格子内容宽，内边距 6px 8px（≈），圆角 6。
- 边框 1px `--ev`，背景 `--paper`，外发光 `0 0 0 3px var(--event-glow)`。
- 第一行 12 / 16 `--text`，光标颜色 `--ev`；预览行离第一行 3，行高 14。
- 只有一行文字时，框高 ≈48。

**预览行怎么显示**

只有**保存会改动你打的字**时才显示：打的已经是规范写法（「15:30 和 A 喝咖啡」「15:00-17:00 开会」「看牙」）就不显示，框只有一行高。双击已有条目时内容本来就规范，打开不显示；没改动就保存不了任何东西，也不显示。判断在 `calendarActions.ts` `inputPreview(raw, initial)`。

| 输入状态 | 预览行 | 什么时候显示 |
|---|---|---|
| 空 | 「↳ 打字，时间会自动识别」，`--text-faint` | 只在新建时；编辑中清空不显示 |
| 识别到时间 | 「↳ 15:30 和 A 喝咖啡」（稿 10/6） | 打的字和「HH:MM 标题」不一样时（「下午3点半…」「9:30 …」） |
| 识别到时间段 | 「↳ 15:00–17:00 开会」 | 同上，规范写法是「HH:MM-HH:MM 标题」 |
| 没识别到时间 | 「↳ 不带时间 · 和 A 喝咖啡」，「不带时间」用 `--text-faint` | 编辑一条原来有时间的条目、把时间删了（告诉你保存后就没有时间了）；或者标题会被整理（多余空格） |
| 只有时间、没有标题 | 「↳ 15:00 还差个标题」，后半句用 `--text-faint`；这时回车没反应 | 总是显示 |

**交互**
- **打开**：双击格子空白处。同一时间只能有一个输入框；在另一格双击时，先按「失焦」规则处理当前这个，再在新格打开。
- **打字**：每次输入都同步解析（规则见 §18），预览行马上跟着变。
- **回车**（输入法不在组合中时）：去掉首尾空格后不为空、标题也不为空 → 保存成这一天的日程，输入框消失，新条目短暂高亮；为空 → 等于取消。
- **Shift+回车**：忽略，不换行【推导】。
- **Esc**（输入法不在组合中时）：取消，丢掉输入内容。
- **失焦**（点别处、切页面、窗口隐藏）：有内容就保存，没内容就取消【推导】。
- **中文输入法**：拼音还在组合中时，回车和 Esc 交给输入法处理，不能当成保存 / 取消（判断 `isComposing` / keyCode 229）。**必须做到。**
- **粘贴多行**：把换行换成空格【推导】。长度上限 200 字【推导】。
- **不弹任何选时间的框**（需求 2.1）。

### 2.7 拖动条目：当天排序与跨天移动（v2 02-3）

**触发**：鼠标左键按住条目并移动 ≥ 4px，条目就被拖起（没有长按等待）。移动不到 4px 松手 = 普通单击（选中）；双击照常编辑。已归档任务的标记不能拖（光标不是 grab）。

**拖动中的样子**

| 元素 | 表现 |
|---|---|
| 拖起的条目 | 跟着指针走；背景 `--elevated`（白天是白色），阴影 `--shadow-pop`，旋转 −2°；文字和图标保持原来的颜色；不接收指针事件 |
| 原位置 | 留一个幽灵，不透明度 0.35 |
| 目标位置 | 指针下面那一天的插入位置出现占位块，文案「放到这里」。占位块高 = 拖起条目的高度（至少 18），1px `--ev` 实线框，圆角 6，背景 `--ev-soft`；文字 11px `--ev-text`，居中。**不合规则的日子不出现占位块** |
| 光标 | 可拖的条目 grab；拖动中整个窗口 grabbing |

**规则**
- 落点 = 松手时指针下面的那一天（只算网格可视区里的格子，滑动中的缓冲行也算），位置按其他条目的中线算。
- **同一天**：条目移到占位块的位置，保存这一天的顺序（和以前一样）。
- **别的日子**：把这条记录的日期改过去，并把它放进目标日的占位位置（同时保存目标日的顺序）：

| 条目 | 改什么 | 规则 |
|---|---|---|
| event 日程 | 日程日期 | 时间、结束时间、标题不变 |
| reminder 待办提醒 | 提醒日 | 提醒时间不变；改了提醒就重新排通知 |
| checkpoint 检查点 / 带日期的等别人 | 关键点日期 | 类型、文字不变；**文字里指向原日期的日期片段一起改**，写法不变（「等审批 · 10/1 查」拖到 10/3 →「等审批 · 10/3 查」；「10月1日」→「10月3日」），这样任务卡、详情和日历一致 |
| start 任务开始 | 任务开始日 | 不能晚于截止日（相等可以） |
| due 任务截止 | 任务截止日 | 不能早于开始日（相等可以） |

- **不合规则**（开始晚于截止、截止早于开始）：落点不显示占位块；松手后条目以 150ms 动画回到原位，Toast（提示型，§15.3）说明原因「开始日不能晚于截止日」「截止日不能早于开始日」，没有撤销。
- **成功**：先在本地把条目挪过去（不闪），再写库；Toast「已移到 10月3日 撤销」，**一次撤销把日期和目标日顺序一起退回**。写库失败：Toast「操作没成功，再试一次」，重新读库恢复原状。
- 在网格可视区以外松手（工具栏、星期行、底部速览胶囊那一条）：回原位，什么都不改。
- **翻周**：拖着条目停在网格上边缘或下边缘 24px 以内（或拖出网格上下）400ms，翻一周（往上 = 更早），之后每 600ms 再翻一周；占位块跟着指针在新的周里出现。格子能滚动时，指针在格子上下边缘 16px 内先自动滚格子，格子滚到头才翻周。
- 拖动中按 Esc：取消，条目回原位。拖动中切页（⌘2）：拖动取消。
- 拖动中禁止双击新建，也不会选中文字；失焦不隐藏窗口（blur guard）。
- 稿上那条深色提示「⠿ 长按拖动，调整当天顺序」是给人看的说明，不做成常驻 UI【推导】。读屏的拖动说明是「拖动条目可调整顺序，或拖到别的日子；拖到网格上下边缘停一下会翻周」。
- 键盘替代【推导】：选中条目后按 ⌥↑ / ⌥↓ 在当天内移动（键盘不跨天）。

**顺序怎么存**
- 每一天存一张顺序表。
- **没手动排过的天，用默认顺序**：日程（没时间的在前，有时间的按时间从早到晚）→ 检查点 → 待办提醒（按任务页待办的顺序）→ 开始 → 截止。同一组里按看板位置排（列号小的在前，同列按列内顺序）。期望结果见 `frontend/src/lib/calendar.test.ts`。
- **手动排过的天**：之后新出现的条目追加到末尾。跨天拖进来的条目按落点存进目标日的顺序表。
- 在日历里拖动**只改日期和这一天的顺序**，不改任务页待办的重要程度顺序。

### 2.8 双击已有条目改文字

| 条目 | 行为 |
|---|---|
| event | 条目原位变成 §2.6 的输入框，预填「HH:MM 标题」（有结束时间就预填「HH:MM-HH:MM 标题」，没有时间就只填标题），光标放在末尾。回车重新识别并保存；Esc 恢复原样；文字清空后回车 = 删除，弹 Toast 可以撤销【推导】 |

| start / due / checkpoint | 不在原位编辑，打开任务详情浮层【推导】 |

### 2.9 2 周 / 4 周【无稿·按规范推导】

- 4 周：行高 ≈173，放得下日期头 + 大约 7 条单行条目，再多就在格内滚动。

- 页签名是「待办」（英文 "To Do"）：这个列表装的是**所有没完成的待办**，不是只装今天的。

### 5.3 Hint

- 页签下面没有提示文字，列表离页签 10（同收件箱输入框）。拖动排序（§5.6）照旧，读屏说明在 `tasks.drag.todoInstructions`。

### 5.4 TodoRow（待办行）

**结构**：`[Checkbox] [Title（可换行）] [Tag（可选，靠右）]`

| 部件 | 尺寸（V3-A 实测；行里没有拖动把手，整行按住竖拖排序） | 令牌 |
|---|---|---|
| 行 | 单行高 32（行距），每多一行字加 20；内边距 6；圆角 8（悬停底色用） | 悬停底 `--fill-3` |
| Checkbox | 16×16，x=38，圆角 4.5，描边 1.5 | 描边 `--text-disabled`，底透明 |
| Checkbox 已勾 | 同尺寸，实心 | 底 `--text-disabled`，勾 `--on-accent` 10px |
| Title | x=63 起，13/400，行高 20，最多换 3 行，超出显示省略号 | `--text`；已完成 `--text-disabled` |
| Tag | 高 20，圆角 6，左右内边距 7，字 11，图标 9，和标题至少空 8 | 见下表 |

**Tag 类型**（只有提醒标签；同一时间只显示一个，按优先级从上往下取）：

| 优先级 | 条件 | 文案 | 图标 | 底 / 字 |
|---|---|---|---|---|
| 1 | 有提醒日，且提醒日 < 今天，还没完成 | `M/D`（+ ` HH:MM`） | `bell-fill` | `--du-soft` / `--du-text`（**无稿**：逾期的提醒） |
| 2 | 有提醒日，提醒日 = 今天 | 「今天」（+ ` 18:00`） | `bell-fill` | `--rm-soft` / `--rm-text` |
| 3 | 有提醒日，提醒日 = 明天 | 「明天」（+ 时间） | `bell-fill` | 同上 |
| 4 | 有提醒日，更晚的日子 | `10/9`（+ 时间） | `bell-fill` | 同上 |
| — | 悬停、且没有提醒日 | 「设提醒」按钮（02-1） | `bell` | `--card` 底 + `--card-stroke` 边 / `--rm-text` |

- 没有提醒日的待办不打标签：没做完的待办照样留在列表里，不显示「昨天顺延 / 顺延 N 天」，由用户自己管。

**状态**

| 状态 | 表现 |
|---|---|
| 默认 | 如上 |
| 悬停 | 行底 `--fill-3`；没有提醒日的行，右侧出「🔔 设提醒」 |
| 编辑中 | 双击标题后变成单行输入框（13，底 `--fill-3`，圆角 6，聚焦描边 1px `--ev`） |
| 刚加入（从收件箱来，03-3） | 行底 `--ev-soft`，保持 ≈3 秒后 400ms 淡出 |
| 拖动中 | 见 §5.6 |
| 已完成 | 勾上后 ≈600ms 再移进「今天完成」，标题变 `--text-disabled`，不划删除线 |
| 深色 | 只换令牌；已勾的方框还是灰色（深色主题导出图）。⚠ V3-C 把已勾方框画成了蓝色，**不采用** |

**交互**

- 点 Checkbox → 勾上 / 取消勾。在「今天完成」里取消勾 → 按原来的 `order` 回到未完成列表。
- 双击标题 → 行内编辑。回车保存，Esc 取消，失焦就保存；内容清空后回车 = 删除这条（有 Toast 可以撤销）。
- 悬停点「设提醒」或者点已有的提醒标签 → 弹出「哪天提醒？」选日期弹层（v2 02-1，规格见 §12）。
- 左右滑（§10.14）：右滑过阈值 = 勾上（「今天完成」里的行 = 取消勾），左滑停出红色「删除」，点了才删（Toast 可撤销）。焦点在行里的控件上时按 Delete / ⌫ 也会打开「删除」并聚焦它。
- 右键菜单（**无稿**）：设提醒 / 删除。
- 拖动排序：见 §5.6。

### 5.5 AddTodoRow「+ 添加待办」

- 默认：`plus` 12 + 「添加待办」13，都是 `--text-faint`，x 和 Checkbox 对齐。悬停时变 `--text-3`。
- 点一下 → 变成输入行（Checkbox 占位 + 输入框，placeholder「添加待办」）。回车 → 新待办加到**未完成列表最后**，输入框留着继续加；Esc 或者内容为空时失焦 → 收起。
- 从收件箱来的待办也加在最后（03-3 稿里它出现在第 2 位，不采用）。

### 5.6 拖动排序（竖向 4px 起拖，不用长按）

| 环节 | 规格 |
|---|---|
| 开始 | 在行上按下（不在 Checkbox、Tag 上），竖着移动 > 4px。先横着动过 6px 就是滑动（§10.14），不再拖。不用长按（同 §2.7）：长按会让慢慢横滑的人被当成拖动，删不掉 |
| 被拖的行 | 浮起来：底 `--card`，影 `--shadow-pop`（没有这个令牌时用 `--modal-shadow`），圆角 10，向右偏 ≈18、旋转 ≈1°，宽度不变，跟着指针走 |
| 放置位 | 目标位置开出一个空位：底 `--fill-2`（v2 实测 ≈#E5E7EC），圆角 8，高度和被拖的行一样；空位左边缘有一个 6px 圆点 `--ev`。其他行用 150ms 动画让位 |
| 范围 | 只能在未完成列表里拖；「今天完成」那组不能拖，也不能拖进去 |
| 自动滚动 | 指针进到列表上 / 下边缘 40px 以内时，列表自动滚动 |
| 放下 | 松手后 150ms 落到空位，写入新的 `order`；日历上同一天的提醒也按这个顺序排（05-1） |
| 取消 | 拖动中按 Esc，或者在列表外面松手 → 回到原位 |

### 5.7 DoneSection「今天完成」

- DoneHeader：`caret-down`（展开）/ `caret-right`（收起）10 `--text-faint` + 「今天完成 2」11 `--text-muted` + 一条 1px `--line` 横线占满中间 + 右边「明早自动归档」11 `--text-faint`。
- 默认展开（04-1、V3-A 都画的是展开）；点标题行可以收起，收起状态记在本机设置（`settings.todoDoneCollapsed`）。
- 「今天完成」0 条时整组不显示。
- 跨日后：`done_date` 早于今天的待办即视为已归档（查询时推导，不写库，architecture §12），从这里消失，出现在归档页。

### 5.8 空状态（**无稿，按规范推导**）

- 没有未完成的待办：列表区显示一行「都做完了」（今天有完成的）或「还没有待办」（没有完成的），13 `--text-disabled`，下面紧跟「+ 添加待办」。

### 6.1 结构

### 6.2 InboxInput

| 项 | 值 |

| 尺寸 | 宽 = 左栏内容宽（274），高 ≈32，页签下方 ≈10 |

### 6.3 InboxRow

| 状态 | 表现（尺寸 ≈） |
|---|---|
| 默认 | 高 ≈37，底 `--fill-3`，圆角 10，内边距 10×12，条与条之间空 8；`tray` 14 `--text-muted` + 文字 13 `--text`，文字可以换行 |

| 深色 | 只换令牌 |

**四个去向**（「今天」和「删掉」是手势，ActionRow 只有两个按钮）：

| 去向 | 怎么做 | 结果 |
|---|---|---|
| 今天 | **右滑**过阈值（露出绿色 `sun`「今天」）；键盘 `T` | 变成待办（没有提醒日），加到未完成列表最后，**不上日历** |
| 定日期 | ActionRow 按钮 `calendar-blank`「定日期」；键盘 `D` | 弹出「排到哪天？」（§12）→ 变成带提醒日的待办，**出现在日历那一天** |
| 变任务 | ActionRow 按钮 `check-square`「变任务」；键盘 `R` | 弹出「变成任务」浮层（§11） |
| 删掉 | **左滑**停出红色「删除」再点；键盘：行上 `⌫` 直接删，按钮上 Delete / ⌫ 打开「删除」 | 删掉（软删除，可以撤销） |

ActionRow 按钮：胶囊，高 24，圆角 99，1px `--line` 描边，底 `--card`，字 12 `--text-2`，图标 13，按钮之间空 6。行的 `aria-keyshortcuts` 写上 ↑↓ / T / D / R / ⌫，读屏能听到。

> 收件箱整理是**四个**去向：今天 / 定日期 / 变任务 / 删掉（v1 旧稿里写过「五个去向」，不采用）。
> v2 02-2 右边那张「每条收件去哪」说明卡是设计注释，**不做进应用**。它的两句话当按钮的 tooltip：「进待办，并在那天的日历格子里出现」「选开始（截止可不选），关键点可加可不加」（「今天」「删掉」是手势，没有按钮，也就没有 tooltip）。

**交互**

- 悬停或焦点在这一条里（含左滑出来的「删除」）时出 ActionRow；鼠标移开、焦点离开后收起（如果这一条的弹层还开着，就保持展开）。
- 双击文字 → 行内编辑（**无稿**）。
- 键盘（**无稿，建议**）：焦点在列表里时，↑↓ 选条目；`T` = 今天，`D` = 定日期，`R` = 变任务，`⌫` = 删掉。

### 6.4 整理后的提示 + 撤销

- 每次整理（今天 / 定日期确定 / 变成任务 / 删掉）之后：这一条从收件箱移走，角标减 1，同时弹出 Toast（§15.3）：
  - 单条：「已进待办」/「已进待办 · 10/5 提醒」/「已变成任务」/「已删掉」+「撤销」
  - Toast 还在的时候又整理了一条 → 合并成一条汇总：「收件箱整理完 3 条：1 条进待办 · 2 条变任务」（数量为 0 的那一类不写；还有「· N 条删掉」；「今天」和「定日期」都算「进待办」）。文案与合并只在 `lib/toasts.ts` 的 `inboxTriageToast` 一处实现，所有整理入口（今天 / 定日期 / 变任务 / 删掉）都调它。
- 「撤销」= 把这条 Toast 汇总的**所有**操作倒着撤回：建出来的待办 / 任务删掉，收件条目按原来的位置放回去，角标恢复。
- 变任务的那张新卡：放到「当前最矮的那一列」的最上面，描边 1.5px `--st` 高亮 ≈3 秒后 400ms 淡出；高亮期间卡片底部左侧多一个绿色收件箱图标（提示「新 · 刚从收件箱变来」，§8.1）。
- 整理完以后页签不切换，还停在收件箱。

和待办「设提醒」是同一个组件，规格见 §12（收件箱用法的差异在 §12.2）。

- 收件箱为空：输入框下面一行「收件箱空了」13 `--text-disabled`；角标隐藏。

## 7. 右栏 · 任务网格（3 列瀑布流）

### 7.1 布局模型

- **固定 3 列，每列是一个独立的有序列表**（任务存 `column` + `order`）。卡片按自己内容的高度排，列与列之间不对齐，不会自动重新排版。
  - 依据：03-3 加了 2 张新卡后，原来的卡**一张都没挪**，新卡分别出现在第 1 列和第 3 列的最上面。这和「每列各自一个列表、新卡放到最矮那一列的最上面」完全吻合。
- **新卡放哪**（变任务、新建任务、从归档恢复）：放到「当前总高度最矮的那一列」的最上面；一样矮就放左边那列。
- 矮卡（没有关键点）和高卡（有关键点）是同一个组件，只是长短不同（§8）。
- 加了关键点卡片变高、删光了变矮：其他卡片用 200ms 动画跟着上下挪。

### 7.2 拖动换位

| 环节 | 规格 |
|---|---|
| 开始 | 在卡片空白处或标题上按下，移动 ≥ 5px 就开始拖。如果按在按钮、关键点圆圈、输入框、滚动区的滚动条上，不触发拖动。不移动直接松手 = 点击（打开详情） |
| 被拖的卡（「浮起」） | 跟着指针走；放大 1.02、旋转 ≈1°；影 `--shadow-pop`（没有就用 `--modal-shadow`）；宽度不变；指针变成 `grabbing` |
| 放置框 | 目标位置出现一个和被拖卡**一样高**的框：底 `--fill-2`，1.5px 虚线 `--track`，圆角 16（**无稿**，照待办行的空位做） |
| 让位 | 目标列里的其他卡用 180ms 动画往下让；被拖卡原来那一列往上收 |
| 跨列 | 可以；指针所在的列 = 目标列，按指针 y 和卡片中线比较决定插在谁前面 |
| 自动滚动 | 指针到网格上 / 下边缘 48px 以内，网格自动滚动 |
| 放下 | 200ms 落到放置框，写入 `column` / `order` |
| 取消 | 拖动中按 Esc，或者在网格外面松手 → 回到原位 |

> ⚠ 空白：需求只说了「拖起时卡片浮起，原位置显示放置框」，任务卡拖动没有画稿；v2 01-2 只画了待办行的拖动。按「原位置显示放置框」理解：拖起来的那一刻，放置框就在原位置，随指针移到目标位置。

### 7.3 空状态（**无稿**）

- 一个任务都没有：网格区中间显示「还没有任务」15/600 `--text-3`，下面「从收件箱「变任务」，或者点右上角「+ 新任务」」12 `--text-muted`。

## 8. 任务卡

### 8.1 结构

**卡片靠图标、位置和颜色说话，不写说明文字**（2026-10-06，以详情面板为样板）：省下来的字放进悬停提示（`components/ui/Tip`）和读屏名字里。提示是深色小气泡（深色主题下反白），停 ≈0.3 秒才弹（指针路过不闪），从触发它的东西里「弹」出来（0.34s 回弹曲线，和详情时间条上关键点的提示同款）；移开、按下、滚动就收；贴着窗口边时往里挪，上面没地方就放下面；系统开了减少动态效果时不弹动画。

```
TaskCard（同一个组件；关键点区可以没有）
├─ TitleRow
│   ├─ Title（单行，超出省略号；右边的图标都很窄，标题能多露几个字）
│   └─ Actions：[⚠ N（有关键点逾期时）] 状态图标 [归档图标（逾期 / 已完成时）]
├─ TimeBar
│   ├─ 一行：左 天数「还剩 **25** 天」（数字放大，永远在左边这个位置）……右 日期范围「9/24 – 9/28」（不设截止是「9/12 – ∞」）
│   └─ 轨道（占满整行宽）
├─ KeyPointList（可选；最多显示 7 行，多了在卡片里滚动）
│   └─ KeyPointRow × n
├─ InlineAddRow（点 + 后才出现）
└─ Footer：左「✓ 3/5」……右 ⊕
```

| 东西 | 平时 | 悬停提示 / 读屏名字 |
|---|---|---|
| ⚠ N | 红底小胶囊：`warning-circle` + 数字 | 「1 步逾期」 |
| 状态图标 | 20 的圆标，和关键点标记同一套图形、大一号（§8.3）：推进中 绿圈 + 半个实心、等待中 橙圈 + 沙漏、未开始 灰虚线圈、逾期 红色实心 +「!」、已完成 绿色实心 + ✓；悬停亮起状态的浅底，各有一个小动作 | 状态名「等待中」；点它 = 状态菜单 |
| 归档图标 | 圆形，`archive`；悬停盒子往上蹦一下 | 「归档」 |
| TimeBar | **天数这一句一直看得到**，数字放大，每张卡都在左上同一个位置，扫一列就能比（§8.4）；右边小字日期范围 | 完整的两句，比如「今天 · 第 17 / 42 天」「还剩 25 天」，两行 |
| ✓ a/b | `check` + 「3/5」，`--text-muted`；全部勾完变绿 | 「已完成 3 / 5」；已完成的任务全勾完时「5 / 5 全部完成 · 点「归档」确认一次」 |
| ⊕ | 圆形 24，只有 `plus`；悬停 + 转 90° | 「加关键点」 |
| 收件箱图标 | 刚从收件箱变来的卡（绿描边期间）左下角一个绿色 `tray-arrow-down`，弹进来 | 「新 · 刚从收件箱变来」 |

### 8.2 尺寸（卡宽 ≈293）

| 项 | 值 |

| 卡片 | 圆角 16；内边距 13（上下）× 16（左右）；描边 1px `--card-stroke`；影 `--card-shadow`；底 `--card` |

### 8.4 TimeBar 各状态（文字计算口径见 §20）

## 9. 关键点标记（Marker）

### 9.1 五种标记（卡片里 15px；详情时间线里 16px）

| 名称 | 画法 | 令牌 |
|---|---|---|
| 已完成 | 实心圆 + 勾（9px） | 圆 `--st`，勾 `--check-glyph`（白天白色、黑夜深色） |
| 逾期 | 空心圆描边 1.5px + 浅红底 + 中间「!」（`exclamation-mark` bold，≈10px） | 描边和「!」`--du`，底 `--du-soft` |
| 等别人 | 空心圆描边 1.5px + 中间沙漏（8px） | `--rm` |
| 检查点 | 空心圆描边 1.5px + 中间实心铃铛（7px） | `--rm` |
| 我来做（没完成） | 空心圆描边 1.5px | `--ring` |

悬停时检查点的铃铛摇一下（从顶上摆），等别人的沙漏翻个面；每次悬停一次，系统开了「减少动态效果」就不动。

### 9.2 类型 × 进度 → 用哪个标记

| | 已完成 | 逾期（§9.3） | 没完成 |
|---|---|---|---|
| 我来做 | 已完成 | 逾期 | 灰圈 |
| 等别人 | 已完成 | 逾期 | 沙漏圈 |
| 检查点 | 已完成 | 逾期 | 铃铛圈 |

- 标记只看「做没做完 + 有没有过期 + 类型」：等别人一直画沙漏，详情时间线里也没有反过来画的实心标记。
- 记一笔（不是关键点）在详情时间线里的标记：「对方」= 空心圆 `--rm` + `envelope-simple`；「我」= 空心圆 `--ring` + `note-pencil`（**无稿**）。

### 9.3 逾期的关键点

**规则**：关键点（三种类型都算，记一笔不算）有自己的日期、日期**早于今天**、还没勾，而且任务没完成、没归档 → 逾期，逾期天数 = 今天 − 日期。日期当天还不算（当天是该做 / 该查的那天）。`lib/keyPoint.ts` `overdueDays` / `overdueByKp`；Rust 的菜单栏红点和 9:00 通知用同一条规则（architecture §11–§12）。

**颜色**：用逾期任务的红（`--du`），不加新颜色。红色在这套界面里的意思就是「截止 / 逾期」（任务逾期是红标签 + `warning-circle`、时间条整条变红），关键点逾期是错过了一个小截止日，同一类。和截止日的区别靠形状：截止 = 红旗，逾期的关键点 = 红圈里一个「!」（和逾期标签的 `warning-circle` 同一个意思）。没用橙色加重：橙色是等别人 / 检查点平时的颜色，逾期放进去会被淹没。

**在哪里能看到**

| 场合 | 怎么显示 |
|---|---|
| 窗口收起（只剩菜单栏 / 托盘图标） | 图标右上角一个红点（有逾期的关键点就有，没有就没有）；每天 9:00 一条系统通知「2 步逾期：交会议 PPT · 找同事过一遍、…」，同时列出今天到期的（architecture §11） |
| 日历页 | 逾期的检查点在过去的日子里不变淡，换成截止的红色 + `warning-circle`（§2.5）；今日速览胶囊最前面「交会议 PPT 有 1 步逾期」（§3） |
| 任务页卡片 | 标题行「⚠ N」胶囊（提示「N 步逾期」）；那一行标记换成逾期、行尾日期变红（提示「逾期 N 天」）；卡片默认滚到第一个逾期的（§8.6） |
| 任务详情 | 日期列 `--du-text` 600；标记换成逾期；行尾「逾期 N 天」标签（`--du-soft` / `--du-text`），类型标签退成悬停才显示；时间条上它的小圆点变成 9px `--du`（§10.2）；打开时默认滚到第一个逾期的 |

**没有「当前」关键点**：任务卡、详情、日历里都不标「当前」。时间进度看时间条，事情进度看关键点标记。「等别人 N 天」怎么算见 §13.3。

### 10.3 时间线顺序（**无稿，按规范推导**）

- 关键点和记一笔共用一个 `order`。
- 新关键点 → 放最后；**带日期的按日期插进去**（见 §10.14）。
- 新记一笔 → 插在「第一个没完成的关键点」前面（也就是「现在」的位置）。这样就是图上的顺序：已完成… → 9/25 对方 → 第一个没完成的 → 以后的。
- 手动顺序：没写日期的关键点可以上下拖动排序；带日期的按日期排，记一笔跟着日期走（做法见 §10.14）。

### 10.4 状态切换（StatusDropdown）

- 菜单（`--elevated` 弹出层，圆角 14，每项高 32）：`◐ 推进中` / `⧗ 等待中` / `● ✓ 已完成`，前面是 14 的状态圆标（§8.3）。当前选中的项右边打勾。
- 「未开始」和「逾期」是推出来的（§0.5），**不在菜单里**。这时下拉胶囊显示推出来的状态，比如「逾期 ⌄」，菜单照样可以选上面三项。
  - ⚠ 需求把「未开始」列成一种状态。这里改成推出来的：开始日没到就是未开始；想让它马上开始，就把开始日改成今天。
- 选「已完成」→ `completed_at` = 今天，卡片变成已完成样式，详情不关；Head 出现实心绿色「归档」按钮。
- 从「已完成」改回推进中 / 等待中 → 清掉 `completed_at`。

### 10.5 改开始 / 截止

- 点「开始」或「截止」小块 → 弹出区间小日历（和 §11.3 同一个组件），先选中被点的那一端；点两下选区间。
- 详情里**开始日可以选过去的日子**（老任务本来就是过去开始的）；截止不能早于开始。
- 勾「不设截止」→ 截止小块变灰、显示「不设截止」；时间块切换成「已进行 N 天」模式（填充 = 关键点比例，不画今天刻度和截止红点）；Row4 提醒开关隐藏。取消勾 → 恢复上一次的截止日；没有上一次就让用户去选。
- Row4「截止前一天提醒我（10/30）」开关（**无稿**；需求里有这个功能，03-1 画在了变任务浮层里）：打开后截止前一天 09:00 发一次系统通知「「交会议 PPT」明天截止」（时间 ≈，可以配置）。
- 每次修改都写进历史。

### 10.6 增删关键点、记一笔

- AddBar：
  - 输入框 placeholder「加一个关键点，比如：补交地址证明（做着做着想到就加）」。
  - 类型下拉：`我来做 / 等别人 / 检查点`，分隔线下面是 `记一笔`。打字时下拉跟着 §19 的自动判断走；手动选过之后就不再自动改。
  - 日期小块：`calendar-blank` + 识别到的日期（比如「10/4」）；没识别到时显示「日期」（`--text-faint`）；点开是单选小日历；有日期时悬停出现 ✕ 清掉。
  - **预览行**（同日历双击输入 §2.6）：打的字里认出日期（§19.1 第 1 步）时，输入框里第一行下面多一行「↳ 12/2 周三 cdn 证书过期，记得续签」= 存下去的样子：`↳` `--text-faint`，日期 `--ev-text` 600 等宽数字（带星期，「下周五」打完就看得到是哪天），文字 `--text-muted`，11 / 14，单行省略号；出现时淡入下移 3px（0.16s）。预览行左边对齐打的字；框往下长高（34 → ≈51），圆角改 17，四个角还是原来胶囊的弧度；类型下拉和日期小块对齐第一行。没认出日期、或手动改过日期（文字按原样存）时没有预览行。只有日期没有字时见 §19.1。
  - 回车 = 加上（存删掉日期以后的文字）；然后类型恢复自动、日期清空，焦点留在输入框里。
- 选「记一笔」时：日期默认今天；回车后加一条记一笔，`who` 默认「对方」；在时间线里点它的标签可以在「对方」和「我」之间切换。
  - 依据：v1 需求原话是「记一笔（对方回了什么 / 我做了什么）」；04-2 写的是「关键点、往来记录全部保留」。
- 每一条**没有悬停按钮**：
  - 改日期 = 点左边的**日期列**，弹出单选小日历；有日期的关键点下面多一个「清掉日期」（记一笔总要有日期，没有这个按钮）。没日期的行平时空着，悬停这一行 / 聚焦时淡淡显示「设日期」（已完成的也一样）。清掉日期以后这一行就能拖了。
  - 改类型 = 点行尾的**类型标签**，弹出菜单「我来做 / 等别人 / 检查点」（图标同 AddBar，当前的打勾）；记一笔的标签照旧是点一下在「对方 / 我」之间切换。记一笔和关键点之间不能互换。
  - 删除 = 左滑出红色「删除」再点（Toast 可以撤销）；或者焦点在行里的控件上按 Delete / ⌫（§10.14）。
- 点 Marker = 勾上 / 取消勾，右滑同样；双击文字 = 行内编辑。
- 记一笔**不算关键点**：不算进「N 个」和「已完成 a / b」、不上日历；但会列在任务卡里（§8.6）。

> ⚠ 冲突：详情图上表头写「7 个 · 已完成 3」，它把 9/25「对方」那条也算进去了。规格只数关键点（这个例子是 6 个）。

### 10.14 手势：滑动完成 / 删除，拖动排序（**无稿**）

**滑动**（详情时间线每一行、待办行（§5.4）、收件箱行（§6.3），同一个组件 `components/ui/SwipeRow`；任务卡里的关键点行 2026-10-06 起不滑，见 §8.6「只在详情里改」，下面写的卡片尺寸留给开关打开时用）：
- 两种手势：鼠标按住横拖；触控板两指横扫（横向 wheel，跟手指方向，自然滚动下取反）。从行上开始的横扫归行，不换页（§1.3）。触控板横扫在手指抬起的那一刻结算（macOS 由 Rust 报告，§1.3），手指停在板上不结算，抬起后的惯性吞掉；拿不到抬起信号时，滚动停 120ms 才结算。和鼠标一样，先动过 6px 才定方向：横着多就是滑动，竖着多就让给列表（滚动 / 排序），一开始带一点点斜也不会把滚动吃掉。
- **向右**：左边露出绿色「完成」（已完成的行是灰色「取消完成」；收件箱是「今天」），拖过阈值（详情 / 左栏 72px、卡片 52px）底色变实心，松手就执行，行弹回原位。过了阈值越拖越沉，最多再多走 20px（卡片 14px，详情时间线 6px：色块只盖住日期列和圆圈，不压到文字），色块不会拉成一长条。向左拉过「删除」按钮的宽度也一样。记一笔不能勾，向右只轻微晃一下。
- **向左**：右边露出红色 `--du`「删除」按钮（详情 / 左栏 88px、卡片 64px），松手时拉开超过一半就停在打开状态，点按钮才删（Toast 可撤销）。一次手势只走一边：往左露出了「删除」（已经停在打开状态，或者手指还没抬起），再往右滑只是合上，滑到原位就停住，拉再多也不会露出「完成」，往回一动马上跟手；先往右的反过来也一样，往回停在原位、不出「删除」。要做另一边的动作，手指抬起后再滑一次（鼠标同理，松开再拖）。打开的行：点它本身、点别处、Esc、在别的行开始滑动、打开浮层或弹层都会合上；同一时间只开一行。
- **键盘**：焦点在行里的控件上（不是输入框）时按 Delete / ⌫ → 打开「删除」并把焦点给它，回车 / 空格删除，Esc 合上、焦点回到原来的控件（那个控件已经不在了就给行里第一个控件）。这些控件带 `aria-keyshortcuts="Delete Backspace"`，读屏能听到。
- 滑动时行里弹出来的东西（日期列的小日历）先收起。
- 拖开时滑动面铺不透明的行底色（深色卡片的半透明底下面再垫一层纸色），只有拉开的那一截露出底下的颜色。
- **详情时间线的行不滑动**（整行滑动会把圆圈和竖线拖走、把文字切掉半个字）：行本身不动，「完成 / 取消完成」从行的左端、「删除」从右端以圆角色块盖进来（`SwipeRow overlay`，圆角 = 行的 12），日期、圆圈、竖线一直在原位。卡片、待办、收件箱的行照旧整行滑动（它们左边没有时间线，裁在列表边上）。
- 动作色块只铺在露出来的那一截（再往行面底下多 12px，免得滑动时露缝），不铺满整行：铺满的话行面底下的红 / 绿会从圆角的抗锯齿边缘透出来，成了另一头的细弧。
- 结束滑动的那一下点击不会落到行上（不会误勾、误开详情）。
- 只读（已归档）详情不能滑；卡片拖动时的浮起副本不能滑。
- 卡片里关键点行不再能拖起整张卡（行内横拖归滑动）；拖卡片按标题、时间条、空白处。
- 小圆圈（Marker）照旧点一下勾上 / 取消勾；可点的圆圈点击区域比画出来的大 5px，悬停时描边变绿 + 浅绿光圈。

**探头**（代替说明文字）：前两次打开详情（本机计数 `cache:detailSwipeHint`）时，第一个没完成的关键点在 450ms 后自己往左滑一点（露出红色「删除」）、回来、往右滑一点（露出「完成」）、回来，每段 275ms。每个详情只播一次（去「查看历史」再回来不重播）；只读详情不播；系统开了减少动态效果时不播；按一下、滑一下就停。

**拖动排序**（只在详情时间线；手感和日历条目 §2.7 统一）：
- 能拖的：**没写日期**的关键点，完成没完成都行（日期列只显示自己的日期，所以「日期列空着 = 能拖」）。鼠标放上去是抓手指针（不再有 ⠿ 把手），整行按住竖着移动 > 4px 就拿起（同日历、待办；横着先过 6px 是滑动）。
- 拖动中：一份副本跟着指针上下走（`--elevated` 底、`--shadow-pop`、旋转 −1°，日历是 −2°，这一行比日历条目宽十倍，转 2° 两头晃得太大）；「放到这里」占位块（高 = 这一行，1px `--ev`，底 `--ev-soft`，字 11 `--ev-text`，圆角 12）标出落点；整个窗口是 grabbing 指针。**列表总高不变**：拿起时原位置那一行自己变成占位块；拖到别处时原位置收起、占位块出现在落点，任何时候只有一个行高的空位（原位置留幽灵、再插一个占位块的话，列表会多出一行，居中的详情框上下各长半行，手底下的东西跟着挪）。落点按其他行的中线算（不算空位撑开的那一截），越过邻居的中线就换位。日历条目照旧留幽灵（格子高度本来就随内容变）。松手 = 放下（先在本地挪过去再写库）；Esc 或落点就是原位 = 副本 150ms 飞回原位，什么都不改。
- 不能拖的：带日期的关键点（按日期排）、记一笔（总有日期）。它们可以当落点，拖动的行可以放在它们之间任何位置。
- 带日期的关键点自己保持日期顺序：新加一个带日期的、或改了日期（含在日历上拖到别的日子）以后，如果它前面有更晚的或后面有更早的带日期关键点，就挪到「第一个更晚的带日期关键点」前面；没有更晚的就放在「最后一个带日期的」后面。位置本来就合适就不动；清掉日期不动。规则在 Rust `db::key_points::date_slot`，`move_key_point` 拒绝移动带日期的行。

### 11.3 选区间的逻辑（「小日历点两下」）

1. 打开时：开始默认 = 今天，截止 = 空，正在选的是「截止」。

   - 正在选「截止」→ 如果 ≥ 开始，设成截止（区间完成）；如果 < 开始，就改成新的开始，继续选截止。
   - 区间已经选好时再点 → 从头开始：这一天变成新的开始。
3. 点 DateFields 里的某一格 → 切到选那一端。
4. 勾「不设截止」→ 截止那一格显示「不设截止」并变灰；点日子只会改开始；RangeHint 写「只选开始 · 从 10/5 开始算」；RemindToggle 隐藏。
5. RangeHint：区间完成 →「点两下选开始和截止 · 共 M 天」；只选了开始 →「再点一下选截止，或勾「不设截止」」。
6. 翻页（**无稿**）：右上 `caret-left` / `caret-right` 每次翻 3 周，上方显示月份。（seed 里「申请海外学校」截止 12/15，只有 3 周的话根本选不到。）

### 11.4 提交

- 「变成任务」随时都能点：标题不能为空（为空时按钮变灰）；没选截止又没勾「不设截止」→ 按「不设截止」处理。

### 11.5 键盘

- 标题写「排到哪天？」（待办「设提醒」里是「哪天提醒？」）。

- 「不提醒」= 关掉弹层，不整理这一条收件箱条目；在待办「设提醒」里 = 清除提醒日。
- 弹层打开时，这一条收件箱保持悬停样式（§6.3）。

### 14.4 分组与排序

- 按**完成那天**分组（任务 = `completed_at`；逾期没做完就归档的任务 = `archived_at`；待办 = `done_at`），组内按时间倒序。
- 组名：今天 · `M/D 周X`；昨天 · `M/D 周X`；本周 · `M/D – M/D`（本周一到前天，**无稿**，图里刚好没有）；上周 · `9/21 – 9/27`（周一到周日）；更早的按旬分：`更早 · 9 月上旬 N 条`（上旬 1–10、中旬 11–20、下旬 21–月底），跨月写「8 月下旬」。
- 「更早」的组默认收起，只显示组名和条数；点开展开。今天 / 昨天 / 本周 / 上周默认展开。

### 14.5 行右侧的 meta 文字（和四张图都对得上的规则）

| 类型 | 拼法 | 例子 |
|---|---|---|
| 任务 | `S → C` + (有关键点 ?「用时 N 天」) + (有截止 ?「提前 N 天 / 按时 / 晚了 N 天」:（有关键点 ?「N 个关键点」）)，段之间用「 · 」 | 「9/20 → 9/30 · 用时 11 天 · 提前 31 天」「9/24 → 9/26 · 按时」「9/10 → 9/26 · 用时 17 天 · 5 个关键点」 |
| 待办 | 「M/D 完成」+ (有提醒日且完成晚于提醒日 ?「逾期 N 天」) | 「9/29 完成」「9/27 完成 · 逾期 1 天」 |

- `S` = 开始日，`C` = 完成日（逾期没做完就归档的用归档日，后面写「没做完」）。
- ⚠ 04-3「课程作业」写的是「9/29 → 10/2」，10/2 是截止日不是完成日；按规则应该是「9/29 → 9/30 · 提前 2 天」。
- 「按时」= 完成日就是截止日，对应卡片上的「当天完成」。

### 14.6 交互

| 操作 | 结果 |
|---|---|
| 点筛选胶囊 | 只看待办 / 只看任务 / 全部；数字是**全部归档**里各类的条数（不受搜索影响） |
| 搜索 | 输入后 150ms 开始筛：标题、关键点文字、记一笔、总结都算；不分大小写；命中的字用 `--ev-soft` 底高亮；只显示有命中的组，「更早」组有命中时自动展开 |
| 搜不到 | 列表区显示「没找到「xxx」」13 `--text-muted` + 文字按钮「清空搜索」`--ev-text`（**无稿**） |
| 点有关键点的任务行 | 展开 / 收起（同一时间可以展开多个）；没有关键点、也没有总结的行点了没反应 |
| 恢复 | 待办 → 回到未完成列表最后（提醒日保留；提醒日已经过去就清掉）；任务 → 回到任务页最矮那一列最上面，保留原来的状态（已完成的还是已完成），高亮 ≈3 秒，以后的日历提醒恢复；Toast「已恢复到任务页 撤销」/「已恢复到待办 撤销」 |
| 查看全部记录 | 打开只读详情（§10.10） |
| ⌘F | 聚焦搜索框 |
| Esc | 搜索框有内容 → 先清空；否则回任务页 |

### 14.7 本月统计（MonthSidebar）

- 「这个月」= 自然月，按完成日算（和 §14.4 一个口径）。
- 两个数：本月完成且已归档的待办数 / 任务数（和 §14.1 的「归档 N」同一口径）。
- Insights（自动生成，条件不满足的那条不显示）：
  1. 「任务 {n} 件里 {k} 件提前完成」：k = 完成日早于截止日的任务数。
  2. 「有关键点的任务平均用时 {avg} 天，其中等别人占{比例}」：avg = 平均「用时」，四舍五入；比例 = Σ等别人天数 / Σ用时；45%–55% 写「一半」，其他写「{p}%」。
  3. 「逾期的只有 {m} 件（{标题}）」：m = 完成晚于截止 / 提醒日的条数；m=0 写「这个月没有逾期」；m≥3 写「逾期的有 {m} 件」，不列标题；标题超过 6 个字截断。
- RulesBox 是固定文案：「归档规则」「待办：勾掉后第二天早上自动归档」「任务：手动点归档，过期不收就变红」「有关键点的：归档时确认一次」。

### 14.8 空状态（**无稿**）

- 一条归档都没有：列表区中间「这里还没有东西」15/600 `--text-3` +「做完的待办第二天会自动收进来，任务点「归档」收进来」12 `--text-muted`；侧栏两个数都是 0，Insights 隐藏。

## 15. 通用浮层框架、Toast、Esc 优先级

### 15.1 模态浮层

**结构**（V3-A-3）

```
.overlay-layer       绝对定位，铺满整张纸 · 圆角 18 · overflow hidden · 层级 100
├─ .scrim            背景 --scrim · backdrop-filter: blur(var(--scrim-blur))
└─ .modal  [role=dialog] [aria-modal=true] [aria-labelledby]
   ├─ .modal-head    标题 20 / 700（≈）· 右侧放状态胶囊 / 关闭按钮
   ├─ .modal-body    内容多时滚动，顶部和底部用 --fade-elevated 渐隐
   └─ .modal-foot?
```

**尺寸和样式**
- 宽档 600（任务详情用这档），窄档 420【推导】。
- 最大高度 = 纸高 − 80（上下各留 40）【推导】，在纸上居中。
- 背景 `--modal`，描边 `--modal-stroke`，阴影 `--modal-shadow`，圆角 22，内边距 24×26。
- 浮层里的分块：底 `--fill-3`，圆角 14。
- 关闭按钮：直径 28 的圆，底 `--fill-2`，里面是 14px 的 × 图标，颜色 `--text-3`。

**遮罩盖住哪里**：整张纸，包括工具栏和速览胶囊；不盖窗口边那一圈 8px 的玻璃。

**交互**
- 打开：遮罩 150ms 淡入；面板不透明度 0→1，同时从 0.98 放大到 1，用时 180ms。
- 关闭：反过来播放，120ms。
- 关闭的方式：点 ×、按 Esc、点遮罩。
- 焦点限制在浮层里；关闭后焦点回到打开它的那个元素。
- 浮层下面的页面不能滚动。
- 同一时间只能有一个模态浮层；弹出层和 Toast 可以叠在它上面。

### 15.2 锚定弹层

- 没有遮罩，跟着触发它的元素定位，用的材质和 §15.1 的面板一样。
- 离触发元素 6，放不下时自动翻到另一侧。
- 点外面或按 Esc 就关闭。
- §12 是它的第一个用例。

### 15.3 Toast（提示条）与撤销

> Toast 是玻璃胶囊（不是深色实心条），6 秒。文案例子：「已从收件箱排到 10/5 撤销」「已删除「看房」 撤销」「已归档「课程作业」 撤销」「收件箱整理完 3 条：1 条进待办 · 2 条变任务 撤销」。

| 项 | 规格 |
|---|---|
| 位置 | 纸底部居中：日历页离纸底 64（速览胶囊上方），其他页离纸底 24；在浮层下面一层（浮层开着时也能看到） |
| 外观 | V3 规定「浮起来的东西用玻璃」：玻璃材质（§1.4），影 `--glass-shadow-float`；高 34，圆角 99，左右内边距 16；`check` 14 `--st` + 13 `--text` + 空 12 +「撤销」13/600 `--ev-text` |
| 时长 | 6 秒；鼠标悬停时暂停计时；新的同类操作会刷新计时并合并文字（§6.4） |
| 撤销 | 点「撤销」或 ⌘Z（Toast 还在、且焦点不在输入框 / 文本域 / 可编辑区里时；在输入框里 ⌘Z 是原生的文字撤销）→ 倒着撤回这条 Toast 里所有操作；撤完后 Toast 变成「已撤销」1.5 秒后消失 |
| 同时 | 只显示一条；不同类的新操作直接替换旧的（旧的就不能再撤销了） |
| 两种语气 | **完成型**（默认）：前面是绿色 `check`。**提示型**（`tone: "notice"`，什么都没发生、只是告诉你为什么）：前面换成 `info` 14 `--text-3`，没有「撤销」——用于拖动被拒（「开始日不能晚于截止日」）、写库失败（「操作没成功，再试一次」）、撤销失败（「撤销没成功」） |
| 放不下 | 最宽 = 纸宽 − 48；文字过长时省略号，「撤销」不缩 |

**用到 Toast 的地方**：收件箱整理、删除待办 / 关键点 / 记一笔、删除日程、日历跨天拖动（「已移到 10月3日」，§2.7）、归档（不管有没有确认）、恢复；提示型见上表。

### 15.4 Esc 的优先级（从高到低）

1. 输入法还在组合中：交给输入法。
2. 正在拖动：取消拖动。
3. 输入框打开着：取消输入。
4. 锚定弹层打开着：关闭弹层。
5. 模态浮层打开着：关闭浮层。
6. 有条目被选中：取消选中。
6½. 在归档页：搜索框有字 → 先清空；否则回任务页（§14.6）。
7. 以上都没有：隐藏窗口。

## 16. 设置面板（无稿，按规范推导）

> 需求和设计图都没有设置页，但「快捷键能改」「失焦隐藏可关」「开机自启」「主题手动」都需要入口。按 §15.1 窄档浮层做，材质全用令牌。

### 16.1 入口

- 菜单栏 / 托盘图标菜单「设置…」（窗口隐藏时先呼出窗口再打开）。
- 工具栏齿轮按钮（§1.3，所有页面都有）。
- 窗口内 ⌘, / Ctrl+,。
- 快捷键注册失败的系统通知：目前点击它只是呼出窗口，不会自动打开设置面板。

### 16.2 结构

```
Modal（窄档 420，§15.1）
├─ Head：「设置」20/700 …… [✕]
├─ Section「呼出」
│   └─ Row：「呼出 WeekPage」…… [Keycaps ⌃ ⌥ Space] [录制]
│       └─ 状态行（有错时）：「这个组合被别的应用占用了，换一个试试」--du-text 12

| Keycaps | 每个键一个小块：高 24，最小宽 24，圆角 6，底 `--control`，影 `--shadow-faint`，字 12/600 `--text-2`；macOS 用符号 ⌘ ⌥ ⌃ ⇧，Windows 用 Ctrl Alt Shift Win |

| 「第一行」说明 | 11 `--text-muted`，在胶囊下面占整行宽（胶囊太宽，和标签挤不下） |
| 高度 | 最小窗口高 680 时面板内容超出，在浮层里滚动 |

### 16.3 交互

- **录制**：点「录制」→ 声明 blur guard → 监听下一次 keydown：必须带 ⌘ / ⌃ / ⌥ 之一（Windows：Ctrl / Alt；只有 ⇧ + F1–F12 例外），且主键是字母、数字、空格、F1–F12 之一；单独按修饰键不算；Esc 取消。收到合法组合 → 调 `update_settings`（Rust 先注销旧的再注册新的，失败回滚旧的）→ 成功：Keycaps 换成新组合，Toast「快捷键已改成 ⌃⌥⇧Space」；失败：状态行红字，Keycaps 保持旧值。
- 保留组合直接拒绝（不发给 Rust）：macOS ⌘Space、⌃Space、⌘Tab（输入法 / Spotlight / 切换应用）；Windows Win+任意、Ctrl+Space、Alt+Tab、Alt+F4。状态行写「这是系统快捷键，换一个吧」。macOS 的默认值 ⌃⌥Space 不在保留之列；它若正被系统快捷键占用（Rust 读 `com.apple.symbolichotkeys`：切换输入法、聚焦搜索等），状态行写明占用的是哪一项、到系统设置哪里关掉，或在这里换一个。
- **主题 / 语言 / 两个开关 / 显示几周 / 第一行**：点了立刻生效、立刻保存（调 `update_settings`，只带改了的那个字段），没有「保存」按钮；点已经选中的那一项什么都不写。设置还没读出来时点主题、语言没有反应。
- **显示几周**：日历立刻按新周数重排，第一行不变（§2.9）。
- **第一行**：「本周」= 今天在第一行；「上周」= 第一行是上周、今天在第二行。改了立刻把日历滑到新的「家」（§2.2）。
- **时区**：原生下拉，第一项「跟随系统（当前系统时区）」，其后是 WebView 认识的全部 IANA 时区（带 GMT 偏移）；选了立刻保存、立刻生效，「今天」跟着换，日历回到新的「家」（§2.2）。Rust 不认识的名字会被拒绝（`update_settings` 返回 invalid）。
- **语言**：立刻整页换语言（§0.8），面板留在原处，焦点留在语言选项上；托盘菜单同时换语言。
- 「退出 WeekPage」：直接退出（`quit_app`），不二次确认。
- Esc / ✕ / 点遮罩关闭。

## 18. 时间识别规则（客户端解析）

**输出**：`{ time: "HH:MM" | null, endTime: "HH:MM" | null, title: string }`。只处理「几点」，**不处理日期**，日期由双击的那个格子决定。

**第 1 步：规范化**（只用来匹配，不改用户原文）
- 全角数字、冒号、字母转成半角。
- 中文冒号「：」当作「:」。
- 中文数字「一…十二」「两」转成阿拉伯数字。

**第 2 步：按优先级找第一个时间表达**（只取最靠左的一个，后面再出现的时间留在标题里）

1. **时间段**：`<开始>(-|~|–|—|到|至)<结束>`。结束时间必须有「点」或「:」，或者继承开始时间的写法；比如「3-5点」，两边共用「点」。
2. **冒号写法**：`H:MM` / `HH:MM`，后面可以跟 am / pm。
3. **点号写法**：`HH.MM`。小时必须是两位数（10–23 或 0X），前面不能是数字、v、¥、$，后面不能跟数字或单位（元、块、%、万、千、kg、斤、米、km、刀…）。（避免把「2.10 版本」「3.50 元」识别成时间）例外：后面跟着 am / pm 时，一位数小时也可以（「3.30pm」）。
4. **am / pm 写法**：`H am|pm|a.m.|p.m.`，大小写都行，数字和后缀之间可以有空格。
5. **点字写法**：`[时段词] N点 [半|一刻|三刻|M分|M] [钟]`。「一刻」= 15 分，「三刻」= 45 分，「3点15」同「3点15分」。前面紧挨着「第」时不算。中文的「一点」（一 = 1）单独出现多半是「一点点」，不算时间，要带「半 / 一刻 / M分 / 钟」或两个字以上的时段词（「一点半」「凌晨一点」）才算。
6. **只有「中午」两个字** → 12:00。

**第 3 步：定上午还是下午**

| 写法 | 规则 |
|---|---|
| am | 12am → 0；其他不变 |
| pm | 小于 12 的 +12 |
| 时段词「凌晨」 | 0–5 不变；12 → 0 |
| 时段词「早上 / 早晨 / 早 / 上午」 | 不变 |
| 时段词「中午」 | 11、12 不变；1–2 → +12 |
| 时段词「下午 / 午后 / 傍晚 / 晚上 / 晚 / 今晚 / 夜里」 | 小于 12 的 +12；「下午12点」= 12:00；「晚上12点」跨午夜、有歧义，不识别 |
| 什么都没写 | 1–6 → +12（需求明确）；0、7–12 不变（「8点看电影」得到 08:00，预览行看得到，用户自己改）；13–23 不变 |
| 时间段的结束时间 | 默认继承开始时间的上下午；算出来 ≤ 开始时间就再 +12 |
| 不合法的值（时 > 23 或分 > 59，比如「24点」「25点」「15:60」） | 不识别 |

**第 4 步：清理标题**
- 把整个匹配到的片段（连同时段词和「钟」）从原文里删掉。
- 去掉首尾空格，以及首尾的 `，,。、:：;；-–—~` 这些标点。
- 连续的空格合并成一个。
- 中间的标点保留。

**第 5 步：标题为空**（比如只输入了「15:00」）：不允许保存，预览行提示「还差个标题」。

**英文写法**（界面是中文也认；规则与上面的中文写法一致，另外多这些）：
- `8pm`、`8:30 am`、`8 p.m.`：同第 2 步的 am / pm 写法（`3 amazing` 不是 3 am）。
- `noon` / `midday` = 12:00，`midnight` = 00:00（`12 noon` 也行）；`8 o'clock` 当「8点钟」，没写 am / pm 时 1–6 按下午。
- `at 8`、`@ 4`、`at 8.30`：at / @ 后面光秃秃的小时按「8点」读（1–6 → 下午，其余不变：`pick up kids at 3` = 15:00，`dinner at 8` = 08:00）。前面的 `at` / `@` / `from` 跟时间一起拿走（`dinner at 7pm` → 标题 `dinner`）。
- 时段词放在小时前或后：`tonight at 8`、`this afternoon at 3:30`、`8 tonight`、`3 in the afternoon`、`10 at night`（= 22:00），规则同中文时段词（`12 at night` 跨午夜，不识别）。单独的 `morning` / `afternoon` / `evening` 要带 at / @ 才算（`tomorrow morning at 9`）。
- 时间段的分隔符还有 `to` / `until` / `till`：`3-5pm`、`3 to 5pm`、`from 3 to 5pm`、`noon to 2pm`。开头一端没写 am / pm 就借结尾那端的（`11-1pm` = 11:00–13:00）；前导 0 的写法（`07:30-9pm`）按 24 小时，不借；两端都是光秃秃的数字（`5 to 7 drinks`）不算；`10pm-1am` 跨午夜，不算时间段，只取开头的 `10pm`。
- 日期词不解析，留在标题里：`today`、`tomorrow`、`next fri` 和「明天」一样。

**已知的取舍**：「整理3点意见」会把「3点」当成时间（已知误判，预览行看得到，可以接受）；「明天下午3点开会」只取 15:00，「明天」留在标题里。

**用例**：`frontend/src/lib/parseTime.test.ts`（中英文写法、边界、不该识别的例子）。

## 19. 关键点输入自动判型

### 19.1 规则（按顺序执行）

**第 0 步 · 清理**：去掉首尾空格；全角数字、「／」换成半角。

**第 1 步 · 找日期**（存进 `date`，**并把这段日期从文字里删掉**，和日程输入删掉时间一样（§18 第 4 步）：「12.2 cdn 证书过期，记得续签」存成日期 12/2 +「cdn 证书过期，记得续签」，日期显示在时间线的日期列、卡片行尾）：
- D1：`M/D`。M 是 1–12，D 是 1–31，前后都不能紧挨着数字、字母或「/」。
- D2：`M月D日` / `M月D号`。
- D3：相对日期。「今天 / 明天 / 后天 / 大后天 / 昨天 / 前天」（「然后天亮」「提前天数」里的不算）；「周X / 星期X / 礼拜X」（X = 一…六、日、天）= 接下来的那一天（今天就是今天）；前面加「这 / 本」= 这周的，「下 / 下个」= 下周的，「下下」= 下下周的，「上」= 上周的（一周从周一算）。「每周五」「一周三次」不算。
- D4：`M.D`（「12.2」），只在打字时认（预览行看得到结果）；存好的文字里不当日期（拖动改日期、日历标题都不碰它）。前面不能是数字、字母、「.」「/」「¥」「$」「第」，后面不能紧跟数字、字母或「.数字」，也不能（隔一个空格）跟单位「元 块 万 千 百 亿 % 倍 斤 米 克 个 岁 页 份 张 次 节 章 条 版 分 秒 小时 公斤 公里 kg km h…」（「预算 3.5 万」「读 2.3 节」）。
- 英文：`today` / `tomorrow` / `yesterday` / `the day after tomorrow`；星期（`friday`、`fri`，前面可加 `next` / `this` / `last`，规则同中文；单独的 `sat` / `sun` 是常用词，要带前缀）；`Dec 2`、`December 2nd`、`2 Dec`、`2nd of December`。紧挨在前面的 `on` / `by` 跟日期一起删（「renew on Friday」→「renew」）。
- 排除：D1、D2 后面（可以隔一个空格）紧跟「页 份 张 个 次 % 倍」→ 不算日期（比如「做完 3/4 页」）。日期不存在的（2/30、13/1）→ 不算。
- 有好几个日期 → 取最靠左的那个（同一位置取长的），只删它；其余的留在文字里。
- 年份（D1、D2、D4、英文月份）：取离今天最近的那一次（往前、往后比较天数，一样近就取往后）。
- 删掉以后整理文字：去掉空了的括号（「去查结果（明天）」→「去查结果」）、合并空格、去掉首尾的 `，,。、:：;；·-–—~` 和落单的句末「.!?」。
- 关键点只记日期，不记时间：「10/1 15:00 打电话给银行」日期取 10/1，存成「15:00 打电话给银行」。
- **手动改了日期就不删**：日期小块里选了别的日子或 ✕ 清掉，文字按原样存（用户在说「这不是日期」或「不是这天」）；选的正好是识别出的那天，照样删。
- **只有日期、没有别的字**（「12.2」「下周五」）：预览行「↳ 12/2 周三 还差内容」，回车和 ↵ 按钮没反应（按钮变淡，点了输入框晃一下，同 useAttention）；失焦 / 新建任务时一起提交的，按原样存（不丢字）。
- 已知误判：「升级 Python 3.12」会认成 3/12（预览行看得到，✕ 清掉日期就按原样存）。早先存的文字里还留着「10/1」这类日期，照旧显示，拖动时照旧跟着改（§2.7）。

**第 2 步 · 判断类型**：用删掉日期以后的文字（「明天等管局回复」→「等管局回复」→ 等别人），再把开头的日期和分隔符（空格、「·」「:」「：」）去掉，得到 `s`。
- R1 **等别人**：`s` 以「等」开头，而且不是以这些词开头：等于、等级、等比、等同、等号、等分、等宽、等高、等距、等差、等式、等效、等量、等边。
- R2 **检查点**：`s` 满足下面任意一条：
  - 包含：检查、确认、核对、核实、复查、查一下、查一遍、查查、去查、再查、看一下、看一遍、看看、过目；
  - 以「查」结尾（比如「10/9 查」「到时候查」）；
  - 「查」后面紧跟：结果、进度、状态、邮件、有没有、是否。
- R3 其他 → **我来做**。
- 优先级：R1 > R2 > R3。
- 「等」只看开头，这是故意的：句子中间顺口带的「等」不算（「催一下，等对方回复」是我来做）。

> 需求原话是「写「查 / 看一下 / 确认」→ 检查点」。如果「包含查」就算，会和设计图冲突：图上「查资料选卡」（详情里标的是我来做）和「查清两所学校的申请要求」（03-3 画的是我来做的圆圈）都会被判错。所以把「查」收窄成上面三种情况。已知误判：「看一下 Stripe Atlas 和闲鱼服务商的区别」会判成检查点（更像我来做），用户点徽标改。

**第 3 步 · 手动改**：点类型徽标或下拉可以改；改过以后这一条不再自动判断。日期可以用 ✕ 清掉。

**用例**：`frontend/src/lib/keyPoint.test.ts`（类型，今天 = 2026-09-30）、`frontend/src/lib/stepInput.test.ts`（日期与删日期后的文字，今天 = 2026-10-06）。

## 20. 任务时间条计算规则

### 20.1 定义

- 所有日期都按本地日期算，不看几点钟。`diff(a, b)` = b − a 的天数（同一天 = 0）。
- 记号：今天 `T`，开始 `S`，截止 `D`（可以没有），完成 `C`。

| 文案 | 公式 | 首尾算不算 | 用在哪 |
|---|---|---|---|
| **共 M 天** / **第 N / M 天**里的 M | M = diff(S, D) + 1 | 开始日、截止日都算 | 有截止的卡 |
| **第 N 天** | N = diff(S, T) + 1 | 开始那天是第 1 天 | 进行中，S ≤ T ≤ D |
| **还剩 X 天** | X = diff(T, D) | 今天不算，截止日算到（截止当天 X=0，写「今天截止」） | 进行中 · 有截止；N + X = M |
| **进度填充** | N / M | 今天算已经过去 | 进行中 · 有截止 |
| **已进行 N 天** | N = diff(S, T) + 1 | 开始那天算第 1 天 | 不设截止 |
| 不设截止的填充 | 已完成关键点数 / 全部关键点数 | — | 不设截止 |
| **还有 N 天** | N = diff(T, S) | 今天不算 | 未开始（T < S） |
| **已过 N 天** | N = diff(D, T) | 截止那天不算逾期，过了截止的第二天写「已过 1 天」 | 逾期（T > D 且没完成） |
| **用时 N 天** | N = diff(min(S, C), C) + 1 | 开始、完成两头都算；比开始还早就完成了 → 1 天 | 已完成 |
| **提前 N 天** | N = diff(C, D)，C < D 时 | — | 已完成 · 有截止 |
| **当天完成 / 按时** | C = D | — | 卡片写「当天完成」，归档页写「按时」 |
| **晚了 N 天** | N = diff(D, C)，C > D 时 | — | 已完成 · 有截止（归档页待办写「逾期 N 天」） |
| **截止前一天提醒** | 日期 = D − 1 | — | 变任务里显示「（10/8）」 |
| 详情里今天刻度的位置 | N / M | — | 详情轨道 |
| 详情里关键点小圆点的位置 | (diff(S, 关键点日期) + 1) / M，超出 0–1 的夹在两端 | — | 详情轨道 |

> 需求原话是「按「已过天数 / 总天数」填充」。图上实际是 **N/M（今天也算过了）**：课程作业量出来是 0.51，正好是 2/4。如果是 (N−1)/M 就会是 1/4。按图来，也就是 N/M。

校验用例（用图上的数字，今天 = 9/30；含 S = D = T、T = D、T = D + 1、C > D、C < S 等边界）见 `frontend/src/lib/taskMath.test.ts`。
